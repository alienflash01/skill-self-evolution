## 详细内容

### Voyager

> `A. 技能库自动构建与进化` · Minecraft agent，通过 automatic curriculum + iterative prompting 持续构建可复用代码技能库

#### 基础信息

**名称：** Voyager
**提出机构**

NVIDIA / Caltech / UT Austin / Stanford / ASU (MineDojo 团队；作者: Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi "Jim" Fan, Anima Anandkumar)
**发布时间：** 2023-05-25 (arXiv v1)
**论文链接：** https://arxiv.org/abs/2305.16291
**代码链接：** https://github.com/MineDojo/Voyager
**类型：** 学术 (同行评审论文，arXiv 预印本；MIT 许可证开源代码)

#### 进化对象 (What)

**进化对象 (What)**

工具/技能 (skill library) + 上下文记忆与提示。一个不断增长的、可执行代码形式的技能库是进化的载体；模型权重不被进化（GPT-4 作为黑盒使用，无微调）。简单技能的组合随时间复合出更强的能力。
**技能是否独立制品：** 是。每个技能都是一个独立可复用的制品 (artifact)：一个自包含的可执行代码程序加一段自然语言描述，经过验证后被提交到持久化技能库（以文件夹形式存储），以便在类似情境下被检索或组合使用。

#### 技能表示

**技能编码方式**

可执行代码（面向 Mineflayer 机器人 API 的 JavaScript 程序，并用 Voyager 工具函数封装），每段代码都配有一条自然语言描述。选择代码作为动作空间，是为了表达时间上延续的、可组合的行为。技能以描述文本的嵌入向量作为索引。
**技能粒度：** 子任务工作流 (sub-task programs)。每个技能完成一个时间上延续的子任务（例如「合成木镐」、「猎杀僵尸」）；复杂技能通过组合更简单的程序合成而来。

#### 自进化机制 (How)

**进化方法范式 (How)**

基于奖励 (reward-based，将环境/执行反馈作为文本奖励) + rollout 优化 (rollout_optimization，通过迭代提示进行文本/代码空间优化，非梯度方法)。迭代提示机制结合环境反馈、执行错误和自我验证来改进程序；不使用任何基于梯度的训练或参数访问。
**学习信号来源**

环境反馈 (环境执行反馈 + 执行错误) + 自我反思 (GPT-4 自我验证作为评判者) + 成败轨迹 (执行成功/失败)。学习完全通过黑盒 GPT-4 查询在上下文 (in-context) 中进行。

#### 进化时机 (When)

**进化时机 (When)：** 测试期内 (intra-test-time，在线，在任务执行过程中)。Voyager 进行持续的终身学习，在一个开放式会话中边游玩边逐步获取/存储技能。
**触发方式**

课程驱动 (GPT-4 自动课程根据智能体状态 + 进度提出下一个探索任务，是一种上下文内的新颖性搜索 (novelty search)) + 失败触发的迭代提示 (在执行错误或自我验证失败时重新生成代码)。

#### 技能存储与检索

**技能库结构：** 向量库 + 技能文件。每个技能 = 一个文件夹，内含可执行代码 + 描述；技能通过其描述的向量嵌入进行索引以支持相似度检索。
**检索/复用方式**

语义相似度 (semantic similarity：嵌入技能描述，为新任务检索 top-5 相关技能) + 代码直接复用 (直接复用代码 / 组合更简单的程序)。该技能库还可作为即插即用资产，用于增强其他方法 (如 AutoGPT)。

#### 验证与反馈

**验证方式：** 基于执行 (在 Minecraft 中运行代码；观察环境反馈 + 执行错误) + LLM 评判/验证门控 (GPT-4 自我验证作为评判者确认任务是否达成；只有通过验证的技能才会被提交到技能库)。
**错误纠正：** 自我修订 (self-revision：迭代提示利用错误信息或批评意见作为反馈，重新生成/编辑程序；在技能被接受或拒绝前进行有限多轮修正)。

#### 环境与基座

**测试环境：** Minecraft (通过 Mineflayer Node.js 机器人 + Mineflayer-collectblock；连接到一个 Fabric 模组化的 Minecraft 1.19 实例)。
**底座模型：** GPT-4 (黑盒 API 查询，用于课程设计、代码生成和自我验证)；消融实验表明 GPT-4 在代码生成上远胜 GPT-3.5。
**部署域 (Where)：** 专用 (specialized，Minecraft / 开放世界游戏环境)。

#### 评估指标

**评估指标**

技能库增长 (skill_library_growth，新发现的独特物品数；技能库规模)、泛化能力 (generalization，在新世界中零样本迁移到未见任务)、样本效率 (sample_efficiency，达到里程碑所需的提示迭代次数)、成功率 (success_rate，科技树工具层级、任务完成度)、探索能力 (exploration，独特物品数、移动地图距离、解锁的科技树里程碑)。
**关键结论**

相比此前 SOTA，获得 3.3 倍更多的独特物品 (160 次迭代内 63 件)，移动距离长 2.3 倍，并以最高 15.3 倍的速度解锁关键科技树里程碑 (木制 15.3 倍、石制 8.5 倍、铁制 6.4 倍；Voyager 是唯一解锁钻石层级的方法)。零样本：在新世界中可解决全部未见任务，而基线方法在 50 次迭代内一个都解决不了。技能库还以即插即用方式增强了 AutoGPT。消融实验：每个模块都很重要，且 GPT-4 >> GPT-3.5。

#### 局限与挑战

**局限与挑战**

### JARVIS-1

> `A. 技能库自动构建与进化` · 开放世界 agent，基于多模态记忆的技能计划与进化

#### 基础信息

**名称：** JARVIS-1
**提出机构：** CraftJarvis 团队 — 北京大学 (PKU)、北京邮电大学 (BUPT)、UCLA、BIGAI（北京通用人工智能研究院）
**发布时间：** 2023-11-10（arXiv v1）；NeurIPS 2023
**论文链接：** https://arxiv.org/abs/2311.05997
**代码链接：** https://github.com/CraftJarvis/JARVIS-1
**类型：** 学术

#### 进化对象 (What)

**进化对象 (What)：** 上下文记忆与提示 — 一个不断增长的多模态记忆库，存储成功执行的规划/技能（目标、计划、里程碑物品），并以上下文示例的形式被检索出来以增强规划能力。不更新模型权重；进化纯粹基于上下文/记忆。
**技能是否独立制品**

是。技能以可复用的记忆条目形式存在于一个多模态键值存储中：键 = （任务文本 + 视觉观测/情境），值 = 成功执行的自然语言动作计划。这些持久化的轨迹是可独立检索、可复用的制品 (artifact)。

#### 技能表示

**技能编码方式**

自然语言计划（有序的合成/挖矿/冶炼子目标序列）配对多模态状态键（任务文本 + 视觉观测）。文本键通过 CLIP 文本编码器嵌入；视觉状态通过 CLIP 视觉编码器嵌入。记忆文件为 assets/memory.json。
**技能粒度**

子任务工作流 — 每个技能是一条由中间子目标/里程碑物品组成的分解链（例如 obtain_wooden_pickaxe -> mine_cobblestone -> craft_furnace -> smelt_iron -> ...）。MLM 还会进行反向子目标分解以供检索。

#### 自进化机制 (How)

**进化方法范式 (How)**

模仿示范 (imitation_demonstration)（自我模仿）— 仅保存成功的轨迹，随后作为检索增强生成 (RAG) 的上下文示例进行检索。由课程驱动的自我指令探索循环加以增强。无梯度更新，无 RL。
**学习信号来源：** 成败轨迹 — 任务是否成功决定了某个计划是否被写入记忆；失败被丢弃，成功被存储并复用。
**奖励粒度：** 结果级 (outcome) — 二值的任务完成情况（在时间预算内获得目标物品）决定记忆存储。
**学习范式**

在线（实时 Minecraft 交互）；同策略 (on-policy)（智能体自身经验）；上下文内（以记忆作为上下文，无梯度）。跨共享记忆的分布式投机执行 (speculative execution) 加速了数据收集。

#### 进化时机 (When)

**进化时机 (When)**

测试间 (inter-test-time)（多轮次自我改进循环：智能体遍历整个任务池 N 个轮次，将经验累积到共享记忆中）与测试内 (intra-test-time)（在一个长周期回合内，随着游戏时间延伸和记忆增长，里程碑物品上的成功率持续上升）两者兼具。
**触发方式：** 跨轮次的课程驱动（由 LLM 自我指令生成、遵循 Minecraft 科技树的任务课程）；加上回合内当某个子目标失败时由失败触发的交互式重规划（自检/自解释）。

#### 技能存储与检索

**技能库结构：** 多模态键值记忆（以任务 + 观测为索引的扁平存储）。条目按任务/子目标组织并配有多模态嵌入；可选地在分布式环境间共享/集中化。通过反向子目标推理进行分层检索。
**检索/复用方式**

通过 CLIP 的语义相似度 — 用查询与任务键之间的文本嵌入相似度筛选候选，再用视觉状态嵌入相似度进行排序；结合「生成即检索」（LLM 反向推理产生子目标文本查询；当前视觉观测被拼接以构成多模态查询）。每个子目标检索出排名最高的条目作为 RAG 示例。

#### 验证与反馈

**验证方式：** 基于执行的验证门控 (gating) — 一个计划只有在环境中被成功执行（获得目标物品）后才会被持久化到记忆。失败的执行不被存储。
**错误纠正：** 自我修订 (self-revision) — MLM 自检发现初始计划中缺失/错误的物品，并由自解释加以修复；在执行失败时，智能体重新感知状态（例如镐子损坏、缺少燃料）并从当前物品栏动态重规划。

#### 环境与基座

**测试环境：** Minecraft（Minecraft Universe Benchmark / MCU；20 FPS 下原生类人观测与动作空间，鼠标 + 键盘）。
**底座模型**

多模态 LM = MineCLIP（视觉-语言基础模型）与一个 LLM 链式连接。测试过的 LLM 选项：GPT-4、ChatGPT、LLaMA2-70B，以及一个在 Minecraft 上微调的 LLaMA2-13B（≈ChatGPT）。底层目标条件控制器 = STEVE-1（基于 VPT 构建）。
**部署域 (Where)：** 通用（开放世界通用多任务智能体）；在 Minecraft 中进行了演示。

#### 评估指标

**评估指标**

成功率（在 >=30 个种子上的回合百分比）、长周期里程碑完成度、技能库增长 (skill library growth)（成功轨迹数量 / 记忆大小）、跨任务迁移（来自检索经验的成功率增益）、跨 LLM 主干和课程的消融。
**关键结论**

(1) 完成 >200 个 MCU 任务，在短周期任务上接近完美表现。(2) ObtainDiamondPickaxe：60 分钟时成功率 12.5%（20 分钟时 6.22%），而 RL 微调的 VPT (SOTA) 为 2.5%/3% — 可靠性提升约 5 倍。(3) 自我改进：在 4 个轮次内累积 425 条成功轨迹，中间里程碑物品上的成功率持续上升。(4) GPT 生成的课程优于人工编写和随机课程。(5) Minecraft 微调的 LLaMA2-13B 与 ChatGPT 相当；原版 LLaMA2-70B 因缺乏 Minecraft 知识而表现不佳。

#### 局限与挑战

**局限与挑战**

可迁移性（仅限 Minecraft/MCU，未展示跨游戏迁移）；控制器执行保真度是钻石级任务的瓶颈（STEVE-1 无法完美执行 LLM 的短周期指令）；LLM 规划幻觉；情境感知规划错误导致低效/失败；开源代码省略了多模态描述符、多模态检索和在线学习模块（仅发布了离线固定记忆评测）。

**技能库结构：** 基于文本：(1) 来自 Minecraft Wiki 和游戏内配方的静态文本知识库；(2) 由成功动作列表摘要构成的扁平、不断增长的文本记忆。

**测试环境：** Minecraft（开放世界、长时程合成/生存任务，ObtainDiamond 基准，完整的 Overworld 科技树）。

### SkillWeaver

> `A. 技能库自动构建与进化` · 分析成功轨迹，合成与精炼可复用 skill API（综述 §3.3）

#### 基础信息

**名称：** SkillWeaver
**提出机构：** 俄亥俄州立大学 (OSU-NLP-Group)、弗吉尼亚大学、普渡大学、卡内基梅隆大学、Cisco Research
**发布时间：** 2025-04-09
**论文链接：** https://arxiv.org/abs/2504.07079
**代码链接：** https://github.com/OSU-NLP-Group/SkillWeaver
**类型：** academic

#### 进化对象 (What)

**进化对象 (What)：** 工具技能 (skill library / API action space)。一个不断增长的、可复用的 Python-API 技能库;不更新任何模型权重——演化完全发生在外部的技能/工件层。
**技能是否独立制品**

是。技能以独立的、即插即用的、可迁移的工件形式存在:Python 函数(Playwright 浏览器自动化代码),每个函数包含签名、docstring(含使用日志 + 前置状态)以及代码体,存储于知识库中并在多个 agent 间共享。

#### 技能表示

**技能编码方式：** 可执行代码 / API。每个技能是一个封装 Playwright 动作的 Python 函数,并附带记录先前执行情况与所需前置条件的自然语言 docstring。
**技能粒度：** 子任务级 workflow。三类任务被抽象为单一可调用的 API:过程型(多步骤自动化)、导航型(站点映射)和信息检索型(抓取)。

#### 自进化机制 (How)

**进化方法范式 (How)**

rollout 优化(非梯度)+ 模仿演示 (imitation demonstration)。三阶段流程:(I)技能提议(LLM 自动课程提出多样化技能)、(II)技能合成(agent 练习任务;LLM 奖励模型判断成功与否;将成功的状态-动作轨迹借助静态分析蒸馏为通用化的 Python API)、(III)技能打磨(自动生成测试用例 + 环境反馈来调试/优化 API)。不涉及任何梯度更新。
**学习信号来源：** 成败轨迹(成功/失败的练习轨迹)+ LLM-as-judge(LLM 奖励模型从轨迹 + 截图 + 环境反馈中提供任务完成信号)。
**奖励粒度：** 结果级(outcome,奖励模型对每次练习尝试判断二元的任务完成是否成功)。
**学习范式：** 在线交互式探索(agent 在真实环境中执行)结合离线技能蒸馏;on-policy(agent 从自身轨迹中学习)。

#### 进化时机 (When)

**进化时机 (When)：** 测试间期 (inter-test-time)。一个自主驱动的课程探索/合成阶段在任务执行之前于新网站上离线运行;随后在测试时复用这些技能。打磨也会在练习期间/之后发生。
**触发方式：** 课程驱动(curriculum,LLM 充当自动课程提出新颖技能)+ 失败触发(测试期间的运行时错误触发 API 修补/恢复)。

#### 技能存储与检索

**技能库结构：** 技能文件 / 按网站划分的扁平知识库。合成的 API 以代码文件形式存储(如 kb_post_code.py)并附带元数据;在多轮探索迭代中不断扩展。

#### 验证与反馈

**验证方式**

基于执行(自动生成的单元测试以独立方式或带 LLM 生成参数运行该 API)+ LLM-judge(奖励模型)+ 验证门控(默认只暴露经过验证、无错误的 API;通过 --allow-unverified-apis 标志控制此行为)。
**错误纠正**

通过有限补丁进行自我修订 (self-revision)。在测试期间的运行时异常发生时(--allow-recovery),agent 定位出错区段(如模糊的 DOM 选择器)并应用定向 diff 以使 API 更加鲁棒。

#### 环境与基座

**测试环境：** Web——WebArena(Gitlab、Map、Shopping、CMS、Reddit)以及真实在线网站(Online-Mind2Web:Drug、Flight、Cooking、Car)。
**底座模型：** GPT-4o(默认 agent / API 合成 / 成功判定 LM);GPT-4o-mini 作为较弱 agent 进行了测试;支持 Azure OpenAI。
**部署域 (Where)：** 专用领域(web/GUI 自动化)。面向通用自主网页导航的 agent。

#### 评估指标

**评估指标：** success_rate(相对提升)、generalization(跨 agent 与跨网站迁移)、skill_library_growth(每轮迭代)、cost。
**关键结论**

WebArena:相对 success rate +31.8%(GPT-4o 22.6→29.8;GPT-4o-mini +45%,在 CMS 上最高 +133%)。真实 Online-Mind2Web:+39.8%(40.2→56.2)。跨 agent 迁移:来自强 agent 的 API 在 WebArena 上将较弱 agent 最多提升 +54.3%。约 160 轮探索迭代即可获得收益。

#### 局限与挑战

**局限与挑战**

可迁移性/可扩展性:依赖 accessibility-tree DOM 解析——无法解析为自然 accessibility 树的网站会阻碍性能;每个网站的探索成本。可控性:agent 有时无法调用或误用生成的 API。技能质量依赖于骨干模型(弱模型会产生有缺陷/不可复用的技能)。

### SkillOpt

> `A. 技能库自动构建与进化` · Microsoft，文本空间技能优化器；技能文档作为可训练外部状态，rollout+reflection+validation gating

#### 基础信息

**名称：** SkillOpt
**提出机构**

Microsoft Research（作者：Yifan Yang, Ziyang Gong, Weiquan Huang, Qihao Yang, Ziwei Zhou, Zisu Huang, Yan Li, Xuemei Gao, Qi Dai, Bei Liu, Kai Qiu, Yuqing Yang, Dongdong Chen, Xue Yang, Chong Luo）
**发布时间：** 2026-05-22（arXiv v1；v2 于 2026-05-25）；PyPI v0.1.0 于 2026-06-02；SkillOpt-Sleep 预览版于 2026-06-15
**论文链接：** https://arxiv.org/abs/2605.23904
**代码链接：** https://github.com/microsoft/SkillOpt（另有 https://aka.ms/skillopt；PyPI: skillopt）
**类型：** 学术（论文）附带开源框架（MIT 许可证，pip install skillopt）

#### 进化对象 (What)

**进化对象 (What)：** 上下文记忆 / 提示词 (prompt) — 将一份紧凑的自然语言技能文档视为冻结 LLM 智能体可训练的外部状态；模型权重不被更新。（类别：技能库 (skill library)）

**技能编码方式：** 技能文档（.md，SKILL.md 格式）— 自然语言过程性指令（无可执行代码，无向量）
**技能粒度：** 策略规则 / 子任务工作流 (workflow) — 一份过程性技能文档（策略规则、启发式方法与子任务流程）

#### 自进化机制 (How)

**进化方法范式 (How)**

rollout_optimization（非梯度，文本空间优化）。镜像权重空间 SGD 的纪律：冻结的目标模型执行带评分的 rollout（前向传播），一个独立的优化器模型对成功/失败的小批量 (minibatch) 进行反思并提出有界的增/删/替换编辑，仅当编辑严格提升留出验证 (held-out validation) 分数时才被接受。使用 epoch、（小）批量大小、文本学习率预算、拒绝编辑缓冲区 (rejected-edit buffer)，以及逐 epoch 的慢速/元更新 (slow/meta update)。非梯度。
**学习信号来源：** 成败轨迹（带评分的 rollout 轨迹：消息、工具调用、验证器反馈、任务元数据、最终分数）+ 优化器侧反思（成功与失败小批量由优化器模型分别反思）+ 留出验证分数作为门控
**奖励粒度：** 混合 — 结果（最终任务分数 / 留出验证分数作为接受门控）结合过程证据（优化器对逐示例 rollout 轨迹分析）
**学习范式**

在线 (online)、同策略 (on-policy) — 每个 epoch 由目标模型使用当前技能收集新的 rollout；离线伴侣 SkillOpt-Sleep 每晚对过往会话进行回放 (replay)

#### 进化时机 (When)

**进化时机 (When)：** 测试时间之间 (inter-test-time)（部署前的离线训练阶段；一个每晚离线自演化的伴侣 'SkillOpt-Sleep' 在留出门控之后巩固已验证的技能）
**触发方式：** 周期性（epoch 驱动的训练循环并带留出选择）；SkillOpt-Sleep 基于事件（每晚回顾过往会话/循环任务）

#### 技能存储与检索

**技能库结构：** 技能文件 — 每个基准/领域优化单一技能文档（best_skill.md），而非多技能向量/图库；每次运行一份技能文件

#### 验证与反馈

**验证方式**

验证门控 (validation gating) — 仅当候选编辑严格提升留出验证分数（selection-best 检查点）时才被接受，将反思转化为“提议-测试”优化而非无条件自我编辑；基于执行的基准分数
**错误纠正**

有界编辑（在文本学习率预算下的有界增/删/替换编辑，防止破坏性重写）+ 拒绝编辑缓冲区（被拒绝的编辑作为负反馈存储，使优化器避免重复有害方向）+ 逐 epoch 慢速/元更新（挽救有用但被跳过的编辑，实现更长时程的记忆而不臃肿部署）

#### 环境与基座

**测试环境**

通用 / 多领域，跨六个基准 — SearchQA, SpreadsheetBench, OfficeQA, DocVQA, LiveMath (LiveMathBench), ALFWorld（具身文本世界）；三种执行框架：直接对话、Codex CLI、Claude Code CLI
**底座模型**

冻结的目标模型：GPT-5.5, GPT-5.4, GPT-5.4-mini, GPT-5.4-nano, GPT-5.2, Qwen3.5-4B, Qwen3.6-35B-A3B；独立的优化器模型（例如 GPT-5.5；亦支持目标模型即优化器的匹配设置）；多后端支持 OpenAI / Azure / Claude / Qwen / MiniMax
**部署域 (Where)：** 通用 — 多领域；作为紧凑的 best_skill.md 部署于编程智能体（Codex CLI, Claude Code CLI, Copilot）及直接对话中

#### 评估指标

**评估指标：** 成功率 (success_rate，任务准确率)、泛化性 (generalization，跨模型/跨框架/跨基准迁移)、成本（零推理时优化器调用）、消融准确率、逐单元格 (cell) 与基线对比
**关键结论**

在全部 52 个评估（模型、基准、框架）单元格上取得最佳或并列最佳；在 GPT-5.5 上将无技能平均准确率提升 +23.5pt（直接对话）、+24.8pt（Codex 循环）、+19.1pt（Claude Code）；在每个基准上击败人类、单次 LLM、Trace2Skill、TextGrad、GEPA 与 EvoSkill 技能；ALFWorld test-hard 70.9%→85.8%；迁移 +15.2pt 跨模型、+31.8pt 跨框架（Codex→Claude Code）、+10.4pt 自优化器；消融实验显示文本学习率、拒绝编辑缓冲区与慢速/元更新各自均贡献增益

#### 局限与挑战

**局限与挑战**

可扩展性 — 每次运行优化单一技能文档，而非完整的多技能库（无检索/索引）；需要任务级验证器 / 带评分的 rollout（需要环境反馈）；增益依赖优化器模型质量（尽管自优化器设置仍可用）；重复 rollout 的训练计算成本；可控性、灾难性遗忘 (catastrophic forgetting) 与评测作弊 (eval-hacking) 已通过有界编辑 + 留出门控 + 缓冲区被显式缓解（是优势而非弱点）

### Reflexion

> `B. 经验/记忆/反思驱动` · 基于自我反思（verbal reinforcement）的能力迭代

#### 基础信息

**名称：** Reflexion
**提出机构**

Northeastern University, Princeton University, MIT（作者：Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao）
**发布时间：** 2023-03-20 (arXiv v1); NeurIPS 2023
**论文链接：** https://arxiv.org/abs/2303.11366
**代码链接：** https://github.com/noahshinn/reflexion
**类型：** 学术（academic）

#### 进化对象 (What)

**进化对象 (What)：** 上下文记忆与提示（无模型权重更新）。智能体策略由自我反思的长期情景记忆与固定LLM参数共同参数化，而非更新权重。
**技能是否独立制品：** 是。自我反思的言语反馈作为独立文本制品存储在情景记忆缓冲区（『mem』）中，跨试验持久化并作为上下文复用。形式：自然语言反思摘要。

#### 技能表示

**技能编码方式：** 自然语言（由LLM生成的自由形式自然语言自我反思文本）。核心方法中无代码/图/嵌入形式（向量/SQL数据库作为未来工作提出）。
**技能粒度：** 见解（insight）。每件制品是从一条完整失败轨迹中提炼出的言语经验/教训（例如『我应该先检查抽屉』），作为可执行的自我提示。

#### 自进化机制 (How)

**进化方法范式 (How)**

基于奖励，通过充当『语义梯度』信号的言语/文本反馈；文本空间中的非梯度策略优化（言语RL）。Actor-Evaluator-Self-Reflection循环将稀疏的标量/二元奖励放大为附加到记忆中的自然语言反馈，以引导下一次试验。无梯度/SFT/RL权重更新。
**学习信号来源：** 混合：环境奖励（编译器/测试执行、精确匹配评分、二元任务成功）、自编写单元测试（编程）、LLM-as-judge/人工编写启发式（决策）以及自我反思（LLM生成的对其自身轨迹的言语批判）。
**奖励粒度：** outcome（每条轨迹/试验一个标量/二元奖励；例如通过/失败、精确匹配、任务完成）。
**学习范式：** online（在线）；on-policy（同策略）（智能体从自身刚生成的轨迹中学习；不进行外部数据的离策略重放）。

#### 进化时机 (When)

**进化时机 (When)：** intra-test-time（测试时间内）（在单次求解中对同一任务重复试验的迭代在线学习；在主实验中不同任务之间重置记忆）。
**触发方式：** 失败触发（failure-triggered）。循环重复执行 Actor->Evaluator->Self-Reflection，直到 Evaluator 通过或达到最大试验预算。

#### 技能存储与检索

**技能库结构：** 扁平（flat，滑动窗口记忆）。保留最后 Omega（通常1-3）条反思条目并前置到上下文；超出窗口的条目被丢弃。论文指出向量数据库/SQL作为未来扩展。
**检索/复用方式：** 直接复用滑动窗口：所有保留的反思被拼接到 Actor 提示中。无语义/向量检索（集合极小），无工作流匹配。

#### 验证与反馈

**验证方式**

基于执行的验证（编程使用编译器+自生成单元测试；AlfWorld使用环境任务成功；HotpotQA使用精确匹配评分），辅以 LLM-judge/人工编写启发式来检测失败/无进展（例如重复动作循环、超过30个动作）。
**错误纠正：** 自我修订（self-revision）：失败时智能体根据其反思的经验条件化地重新生成新尝试；对于代码，它还能识别错误的自我测试并保持先前实现不变以避免有害编辑。

#### 环境与基座

**测试环境**

多样：AlfWorld（文本世界序列决策）、HotpotQA（多跳问答推理）、HumanEval/MBPP/LeetcodeHardGym（Python与Rust代码生成）。LeetcodeHardGym是论文引入的新的40题困难基准。
**底座模型**

模型无关的LLM框架；实验使用 GPT-3（AlfWorld 通过 ReAct few-shot）、GPT-3.5 和 GPT-4（编程/推理）。Chain-of-Thought 和 ReAct 用作 Actor 模块。
**部署域 (Where)：** 通用（general）（跨序列决策、语言推理和编程的通用目的）。

#### 评估指标

**评估指标**

success_rate（AlfWorld 解决的任务数）、pass@1（HumanEval/MBPP/LeetcodeHard）、exact-match 准确率（HotpotQA）；还有测试质量混淆指标（自生成单元测试的 TP/FN/FP/TN）。
**关键结论**

无权重更新/无微调。HumanEval pass@1 = 91%（击败当时 GPT-4 的80% SOTA）。AlfWorld：130/134 任务解决，在12次试验内比 ReAct 基线绝对提升 +22%。HotpotQA：+20% 改进（CoT(GT)+Reflexion 比 CoT(GT) 提升 +14%）。MBPP Rust 75.4%，HumanEval Rust 68%。消融实验表明测试生成和自我反思都是必要的（仅自我反思在 HumanEval-Rust-50 上退化为52%）。

#### 局限与挑战

**局限与挑战**

可扩展性（受上下文长度限制记忆硬性上限为1-3条；无持久跨任务库）；可控性（无形式化成功保证，可能收敛到非最优局部最小值）；eval-hacking（不稳定/自编写测试产生假阳性，例如 MBPP-Python 由于16.3%假阳性测试率退化至 GPT-4 基线以下）；可迁移性（反思是任务特定的，每个任务重置记忆）；对 LLM 自我评估能力的强依赖；依赖隔离沙箱进行自主代码执行。

### ExpeL

> `B. 经验/记忆/反思驱动` · 从经验中蒸馏可复用见解/规则

#### 基础信息

**名称：** ExpeL
**提出机构：** 清华大学 (LeapLab THU)
**发布时间：** 2023-08-20 (arXiv v1); 录用为 AAAI 2024 (口头报告)
**论文链接：** https://arxiv.org/abs/2308.10144
**代码链接：** https://github.com/LeapLabTHU/ExpeL
**类型：** 学术

#### 进化对象 (What)

**进化对象 (What)：** 上下文（记忆与提示）；无参数化/权重更新。抽取的洞见和检索得到的成功轨迹在推理时注入到智能体提示中。
**技能是否独立制品：** 是。两种可复用的制品形态：（1）一组自然语言洞见/规则，每条带有一个重要性计数；（2）存于向量数据库的成功轨迹池，用于后续召回。

#### 技能表示

**技能编码方式：** 自然语言（自然语言洞见/规则 + 自然语言轨迹转写）。不使用可执行代码或学习得到的嵌入作为技能本身（嵌入仅用于检索）。
**技能粒度：** 混合：跨任务洞见（策略规则/最佳实践）+ 子任务工作流（完整成功轨迹作为少样本示范复用）。

#### 自进化机制 (How)

**学习信号来源：** 来自智能体自身尝试的成功与失败轨迹（环境交互的结果），以及 LLM 对失败尝试的自我反思。
**奖励粒度：** outcome（每条轨迹二元任务成功/失败；WebShop 还使用 [0,1] 区间的连续奖励分数 r）。

#### 进化时机 (When)

**进化时机 (When)：** inter-test-time（训练与评估任务之间的离线学习；明确区别于 Reflexion 的任务内重试）。
**触发方式：** 任务/课程驱动（在一系列训练任务上迭代），外加收集阶段由失败触发的反思（失败时自我反思并重试，最多 Z 次）。

#### 技能存储与检索

**技能库结构：** 混合：成功轨迹的 Faiss 向量库 + 带可变重要性计数的洞见平铺列表（ADD/UPVOTE/DOWNVOTE/EDIT；计数降至 0 时裁剪洞见）。
**检索/复用方式：** 语义相似度（通过 Faiss 对 all-mpnet-base-v2 嵌入做任务相似度 kNN）取 top-k 成功轨迹作为少样本示范；完整洞见列表直接拼接到任务指令中（洞见暂不做检索）。

#### 验证与反馈

**验证方式：** 基于执行（环境成功/失败标签标注轨迹），加上洞见抽取阶段由 LLM-as-judge 验证把关（洞见 LLM 的 UPVOTE/DOWNVOTE/EDIT 操作符与重要性计数裁剪过滤低质量洞见）。
**错误纠正：** 收集阶段的 Reflexion 式反思自修订（失败后重新尝试）；通过 EDIT 操作符对洞见进行有界编辑；涌现的任务内自我纠正（例如在 ALFWorld 中放回错误的物品）。

#### 环境与基座

**测试环境：** HotpotQA（多跳问答）、ALFWorld（文本家务具身）、WebShop（网络购物）、FEVER（事实验证）。均为文本观测基准。
**底座模型：** GPT-3.5-turbo-0613 用于动作/策略与反思；GPT-4-0613 用于洞见抽取（消融显示 GPT-4 在洞见抽取上优于 GPT-3.5）。
**部署域 (Where)：** 通用（多样的决策/问答/工具使用领域）；展示了从 HotpotQA（源）到 FEVER（目标）的迁移学习。

#### 评估指标

**评估指标**

success_rate（主要指标；HotpotQA/FEVER 为精确匹配，ALFWorld 为任务完成，WebShop 为全属性匹配）、WebShop 平均奖励、ALFWorld 分任务类型统计、泛化/迁移、LLM API 成本。
**关键结论**

在 HotpotQA、ALFWorld、WebShop 上一致超过 ReAct/Act 基线（4 折，均值 +/- 标准误）。在 HotpotQA 上与 Reflexion R3 持平（约 39% 对 40%），且在 ALFWorld 上无重试即胜出（59% 对 54%）。仅洞见与仅检索的消融互为补充/协同（例如 HotpotQA 36%/31%、ALFWorld 50%/55%、WebShop 37%/38%）。HotpotQA->FEVER 正向迁移。报告了涌现能力：假设生成、世界模型信念更新以及自我纠正。

#### 局限与挑战

**局限与挑战**

可扩展性（洞见适配当前上下文窗口，但终身学习需要对洞见做检索）、可迁移性（仅文本观测；无图像/VLM 输入）、可控性（基于提示，缺乏 RL 那样的理论基础）、依赖闭源 API LLM（GPT-3.5/GPT-4）、WebShop 上相较 Reflexion 仍有提升空间。

### Self-Refine

> `B. 经验/记忆/反思驱动` · 自我迭代优化输出

#### 基础信息

**名称：** Self-Refine
**提出机构**

Carnegie Mellon University (CMU) / Allen Institute for AI (AllenAI)；合作者来自 University of Washington、NVIDIA、UC San Diego、Google Research
**发布时间：** 2023-03-30 (arXiv v1); 2023-05-25 (v2)
**论文链接：** https://arxiv.org/abs/2303.17651
**类型：** 学术（academic）

#### 进化对象 (What)

**进化对象 (What)：** 上下文记忆与提示（context/prompt，推理时）。不改变模型权重或架构；单一 LLM 通过仅依赖提示的迭代，复用为生成器、评论器与精炼器。
**技能是否独立制品：** 否。精炼过程（反馈+改进输出）是临时的，仅在单次任务运行中消费；不会在任务或会话之间持久化任何可复用的技能产物。

#### 技能表示

**技能编码方式：** 自然语言（natural-language feedback 与精炼输出）。反馈是可操作的文本，涵盖问题定位+改进指令。
**技能粒度：** 策略规则/见解（insight-level actionable feedback）。多维度、局部化的批评，指导局部编辑，而非原子动作或完整工作流。

#### 自进化机制 (How)

**进化方法范式 (How)**

rollout_optimization（文本空间、非梯度）结合基于奖励的自我反馈。FEEDBACK->REFINE 循环：同一 LLM 生成内部文本奖励（critique），然后基于该反馈重新解码输出，迭代直至满足停止准则。无 SFT、无 RL、无额外权重。
**学习信号来源：** 自我反思 / LLM-as-judge（self）。生成输出的同一 LLM 也对其批评；无需外部人类或环境反馈。
**奖励粒度：** process（过程）。反馈精确定位具体方面/位置，并给出具体改进指令，而非仅给出标量结果分数。
**学习范式：** online；on-policy（在线；同策略）。生成、批评与精炼都在测试时使用模型自身的输出进行（无离线数据、无异策略语料）。

#### 进化时机 (When)

**进化时机 (When)：** intra-test-time（测试时内部）。反馈-精炼循环在单次任务推理期间在线运行；任务之间不学习/训练任何内容。
**触发方式：** 事件触发（基于初始输出生成的事件触发）。循环在初始输出 y0 之后开始，重复直至满足 is_refinement_sufficient（停止准则）或达到最大迭代上限。

#### 技能存储与检索

**技能库结构：** 无持久技能库（none）。仅通过将先前输出追加到提示中来保留任务内历史；无跨任务或持久化库/向量存储/图。
**检索/复用方式：** 无检索（none / 仅上下文内历史）。过去的迭代被追加到运行提示中，而非从存储中检索；不使用语义/关键词检索。

#### 验证与反馈

**验证方式：** LLM-judge（自我反馈充当验证器）+ 验证门控（is_refinement_sufficient 停止函数）。外部评估使用人类偏好与任务特定的自动指标。
**错误纠正：** 自我修订（self-revision）。REFINE 模块在可操作反馈的指导下重写输出；限制为有限次迭代以避免无限循环。

#### 环境与基座

**测试环境：** 通用（general）。7 项多样的基准任务：对话响应生成、代码优化、数学推理（GSM）、首字母缩写生成、故事生成、情感反转/评论改写、毒性去除、常识/约束生成。
**底座模型：** GPT-3.5（text-davinci-003）、ChatGPT、GPT-4（闭源 LLM）。
**部署域 (Where)：** general（通用文本生成/精炼；未专门针对单一垂直领域）。

#### 评估指标

**评估指标**

人类偏好率（成对人类评估）与任务特定的自动指标（例如代码用 pass@k、数学用 accuracy、对话与改写用 BLEU/ROUGE/BERTScore、概念覆盖率、首字母缩写得分）。还报告了每次迭代的迭代改进率。

#### 局限与挑战

**局限与挑战**

1) 可迁移性/能力依赖：有效性依赖于模型自身的自我反思能力；较弱的模型（如 GPT-3.5）常给出糟糕或误导性的反馈。2) 少数几次迭代后出现递减/负收益（过度精炼可能降低输出质量）。3) 可扩展性/成本：每个任务多次额外的 LLM 调用增加延迟与 token 成本。4) 无持久学习：无技能库、无跨任务记忆，因此增益不会累积。5) 可控性/评估作弊风险：不正确的自我反馈可能将精炼引导向更差的输出。

### Agent Workflow Memory

> `B. 经验/记忆/反思驱动` · 记录可复用子任务序列（workflow），检索已验证行动链代替重规划（综述 §3.2.1）

#### 基础信息

**名称：** Agent Workflow Memory (AWM)
**提出机构：** 卡内基梅隆大学与 MIT（作者：Zora Zhiruo Wang、Daniel Fried、Graham Neubig [CMU]；Jiayuan Mao [MIT]）
**发布时间：** 2024-09-11（arXiv v1；后被 ICML 2025 收录）
**论文链接：** https://arxiv.org/abs/2409.07429
**代码链接：** https://github.com/zorazrw/agent-workflow-memory
**类型：** 学术

#### 进化对象 (What)

**进化对象 (What)：** 上下文记忆与提示（Context memory & prompt）——归纳得到的工作流被集成到智能体的文本记忆 M（系统/辅助提示）中；不更新模型权重。
**技能是否独立制品：** 是——每个工作流是一个独立可复用的制品，由自然语言描述（高层目标）+ 步骤轨迹（环境状态描述、智能体推理、可执行动作）组成，抽象掉示例特有的上下文；存储在工作流记忆中。

#### 技能表示

**技能编码方式：** 自然语言（natural language）——工作流描述加上作为可执行程序的自然语言状态描述与动作（如 CLICK、TYPE、stop()）；以文本块的形式切分存储。
**技能粒度：** 子任务工作流（sub-task workflows）——比完整任务更细粒度的通用可复用子例程，如『搜索某商品』『按名称查找某地点』，将示例特有的取值抽象为占位符如 {product-name}。

#### 自进化机制 (How)

**进化方法范式 (How)**

rollout_optimization（非梯度、文本空间优化）——基于 LM 的归纳模块 I 提示智能体从经验轨迹中提取通用子例程，并抽象掉示例特有的上下文；无梯度/SFT/RL。运行于两种模式：(a) 离线：从带真值标注的训练示例中归纳工作流；(b) 在线：在流式测试推理过程中从自生成的成功轨迹中归纳。
**学习信号来源**

成败轨迹（success/failure trajectories）——离线使用真值标注的演示；在线使用自生成轨迹，由基于 LM 的评估器（Pan 等 2024 AutoEval 二元标签）判定为成功，仅从判定为成功的经验中归纳工作流。
**奖励粒度：** outcome（在线门控使用二元任务级成功标签；无逐步/过程奖励）。
**学习范式：** 离线与在线皆有。离线=off-policy（测试前从给定标注示例中归纳）。在线=on-policy 流式（在测试查询上从智能体自身的预测轨迹中归纳，形成『归纳-集成-利用』的流式循环）。

#### 进化时机 (When)

**进化时机 (When)：** 测试中与测试间皆有。在线 AWM 在任务执行/流式测试期间演化（intra-test-time）；离线 AWM 在测试时推理之前归纳工作流（inter-test-time）。
**触发方式**

事件触发（event-driven）——在线：在每个被评估器判定为成功的测试任务之后，触发工作流归纳与记忆更新；离线：在推理前从某网站的全部训练示例批量归纳。滚雪球/课程式效应在早期工作流之上构建越来越复杂的工作流。

#### 技能存储与检索

**技能库结构：** 扁平（flat）——工作流以独立文本段形式存储于扁平的工作流记忆中，按网站分组/切分；每个网站维护一小批相关工作流。（无层次/向量/图结构；纯文本块。）
**检索/复用方式**

工作流匹配 / 上下文增强——工作流按网站分组；相关网站的全部已归纳工作流被集成到智能体提示上下文中（M + W）以引导生成。智能体学会选择性地遵循或偏离工作流指南。（无语义向量检索；网站级分组 + 全量注入上下文。）

#### 验证与反馈

**验证方式**

执行验证（execution-based），在 WebArena 上通过功能正确性检查；在线使用 LLM 评判门控（基于 LM 的评估器模块在归纳工作流前判定任务成功与否）。Mind2Web 使用元素/动作准确率。在线归纳由评估器成功标签门控（验证门控）。

#### 环境与基座

**测试环境**

Web（网页导航）——WebArena（812 个任务，5 个网站：电商/CMS/Reddit/GitLab/Maps）和 Mind2Web（1000+ 任务，200+ 域；跨任务/跨网站/跨域划分）。
**底座模型：** 主要使用 GPT-4（gpt-4-0613）；也使用 GPT-3.5-turbo。温度 0.0。工作流归纳与动作生成使用同一 LM。
**部署域 (Where)：** 通用（通用网页/GUI 导航智能体；在多样化领域得到验证：旅行、购物、社交媒体、内容管理、开发协作、地图）。

#### 评估指标

**评估指标：** success_rate（任务与步骤成功率）、泛化（跨任务/跨网站/跨域）、cost（每任务平均步数）、元素准确率、动作 F1、样本效率（随示例数量的学习曲线）。
**关键结论**

WebArena：成功率 35.5%，较 BrowserGym 基线（23.5%）绝对提升 +12.0 / 相对提升 +51.1%；较 SteP（人类专家工作流）相对提升 +7.6%；SOTA 35.6%；每任务约少 2 步，较 AutoEval 约少 40.8 步。Mind2Web：步骤成功率相对提升 +24.6%；离线 AWM_4 步骤 SR 45.1 vs MindAct 36.2。在线 AWM 在跨任务/网站/域中绝对提升 +8.9–14.0 步骤 SR 点，且训练-测试分布差距越大，优势越明显。仅从约 40 个示例中学习（快速样本效率）。

#### 局限与挑战

**局限与挑战**

可迁移性（在线从不完美的自预测中归纳出错误工作流，可能降低性能；工作流是领域/网站特有的）/ 可扩展性（随工作流记忆累积，提示上下文增长，提高上下文长度成本）/ 工作流引导可能偏向元素选择（动作 F1 略低于 MindAct；智能体难以判断何时偏离工作流）/ 在线质量受轨迹与评估器精度上界约束。

- error_correction

### ReasoningBank

> `B. 经验/记忆/反思驱动` · 从成败中蒸馏可泛化推理策略到结构化记忆 + memory-aware test-time scaling（综述 §3.2.1）

#### 基础信息

**名称：** ReasoningBank
**提出机构：** Google Research (与 Jiawei Han, UIUC 合作)
**发布时间：** 2025-09-29

**类型：** 学术

**进化对象 (What)：** 上下文记忆与提示 (智能体记忆/推理策略库；不更新权重)
**技能是否独立制品：** 是 - 结构化的自然语言记忆条目，每条包含标题/描述/内容 (提炼的推理步骤、决策依据、操作性见解)

**进化时机 (When)：** 测试间 (跨任务流的持续检索-抽取-整合循环) + 测试内 (任务内的 MaTTS 扩展)

#### 环境与基座

**底座模型：** Gemini-2.5-Flash (以 ReAct 提示为基础)
**部署域 (Where)：** 通用 (网页浏览 + 软件工程智能体任务)

#### 评估指标

**评估指标：** success_rate + 成本/效率 (任务步骤数); 跨持久任务流的泛化能力
**关键结论**

WebArena 上 +8.3% 成功率，SWE-Bench-Verified 上 +4.6% (对比无记忆 ReAct); SWE-Bench 上每任务约少 3 个执行步骤; 优于 Synapse (轨迹) 与 AWM (工作流) 记忆方法; MaTTS (k=5 并行) 在 WebArena 上额外提升约 +3%; 简单清单可涌现演化为组合式预防性策略

### ToolMem

> `C. 技能/工具掌握与精炼` · 存储每个工具/技能的优缺点于记忆，用于更好选择（综述 §3.3）

**类型：** 学术

#### 进化对象 (What)

**进化对象 (What)：** 上下文记忆与提示（可学习的工具能力记忆，存储每个工具的优势/弱点）

#### 进化时机 (When)

#### 技能存储与检索

**技能库结构：** 层次化（熟练度类别：熟练/良好/差/弱）+ 向量库（每个类别的嵌入索引）

**验证方式：** 基于执行（对工具输出的质量反馈）+ 留出集评估（预测用MAE/RMSE/Pearson，选择用F1/Acc）

#### 环境与基座

**测试环境：** 工具调用/通用（在BIGGEN-Bench上的文本生成 & 在GENAI-BENCH上的文生图）
**底座模型：** GPT-4o（agent的LLM）+ text-embedding-ada-002（检索）
**部署域 (Where)：** 通用（多模态生成式工具选择）

#### 评估指标

**评估指标：** MAE/RMSE/Pearson相关性（工具性能预测）；F1与准确率（最优工具选择）
**关键结论**

#### 局限与挑战

**局限与挑战：** 可扩展性（记忆维护；明确列为未来工作）；迁移性（仅限文本与图像生成工具；扩展到更广工具为未来工作）；对反馈机制的依赖（图像生成需要人工标注）

### DRAFT (From Exploration to Mastery)

> `C. 技能/工具掌握与精炼` · 迭代自纠正循环掌握/调试/精炼工具（credit-assignment + docstring refinement）（综述 §3.3）

#### 基础信息

**名称：** DRAFT（从探索到精通）
**提出机构：** 中国人民大学（高瓴人工智能学院）与百度公司
**发布时间：** 2024-10-10（arXiv v1）；被 ICLR 2025 接收（Oral 口头报告，前 1.8%）
**论文链接：** https://arxiv.org/abs/2410.08197
**代码链接：** https://github.com/quchangle1/DRAFT
**类型：** academic（学术）

#### 进化对象 (What)

**进化对象 (What)：** Context 记忆与提示 — 演化的是作为上下文喂给 LLM 的自然语言工具文档/docstring（描述 + 参数），而非模型权重，也非工具代码本身。
**技能是否独立制品：** 是 — 精炼后的工具文档是一个独立、可复用的文本制品（按工具粒度的 JSON：name/description/parameters），可移植并可在不同 LLM 之间共享（跨模型）。

#### 技能表示

**技能编码方式：** 自然语言（结构化的自然语言工具文档 / docstring；以 JSON 格式组织，包含 description 与 parameter 字段）。
**技能粒度：** 面向单个工具的使用文档，处于 insight/guideline 层级（阐明单个工具的用途、参数、返回字段、边界情形及使用示例）。

#### 自进化机制 (How)

**进化方法范式 (How)**

rollout_optimization（非梯度、文本空间的迭代重写）+ 基于奖励的文本反馈：一个自驱动的试错循环，包含三个角色 — Explorer（生成多样化的工具使用尝试）、Analyzer（作为 LLM-as-judge 进行信用分配，将失败归因于具体的文档缺陷，并输出自然语言而非标量建议）、Rewriter（更新 docstring）。包含促进多样性的探索（余弦相似度约束 + 自我反思）以及工具自适应终止。
**学习信号来源：** 成败轨迹（工具执行结果 / 尝试的返回结果）+ 自我反思（Explorer 对重复查询的自我反思）+ LLM-as-judge（Analyzer 对照执行反馈评判文档）。
**学习范式：** offline（文档库在推理前被精炼）；on-policy（骨干模型利用自身的工具使用反馈来精炼文档）。

#### 进化时机 (When)

**进化时机 (When)：** inter-test-time（在下游推理之前离线精炼工具文档库）。
**触发方式：** 周期性 / 迭代驱动（固定最多 5 轮）结合基于收敛的终止（当连续文档相似度变化量 Δ > τ 时工具自适应停止）。

#### 技能存储与检索

**技能库结构：** flat（扁平；每个工具一份文档文件的扁平集合；每个工具一份修订后的文档）。
**检索/复用方式：** 直接复用 — 精炼后的工具文档原样作为推理时智能体的上下文文档（无语义技能检索）。

#### 验证与反馈

**验证方式**

基于执行（真实工具 / API 执行反馈驱动每次尝试）+ 验证门控（通过 BLEU + 余弦相似度阈值 τ=0.75 实现工具自适应终止）；下游评估使用 Correct Path Rate 与 Win Rate。
**错误纠正：** 自我修订 — Rewriter 在 Analyzer 建议与执行反馈的引导下迭代修正文档，并进行有界迭代以避免过拟合。

#### 环境与基座

**测试环境：** tool-call（ToolBench I3-Instruction / RapidAPI，RestBench TMDB 与 Spotify REST API）。
**底座模型：** GPT-4o（DRAFT 的主要骨干）；也测试了 Llama-3-70B 作为骨干；在 GPT-4o、GPT-4o-mini、Llama-3-70B 上进行了评估。

#### 评估指标

**评估指标**

success_rate（Correct Path Rate CP%、由 ChatGPT 评估器给出的 Win Rate）、generalization（精炼文档的跨模型迁移）、cost（token 消耗 / API 成本）。
**关键结论**

LLM 更偏好 DRAFT 精炼后的文档：RestBench-TMDB 92.5%、RestBench-Spotify 77.5%、ToolBench 87.9%。GPT-4o 的 CP% 提升：TMDB 71→88、Spotify 28.07→70.17、ToolBench 37→51；GPT-4o-mini+DRAFT（CP 47）在 ToolBench 上超过 GPT-4o 基线（37）。稳健的跨模型泛化（由一个骨干精炼的文档对所有模型都有帮助）。消融实验证实促进多样性的探索与工具自适应终止均有贡献；性能在达到峰值后因迭代过多而下降。ICLR 2025 Oral（1.8%）。

#### 局限与挑战

**局限与挑战**

scalability 可扩展性（每个工具的迭代 API 成本高；对大型工具集而言昂贵）、transferability 可迁移性（仅在工具调用基准上评估，无其他领域）、overfitting risk 过拟合风险（迭代过多后性能下降，终止机制有所缓解但未消除）、backbone-dependence 骨干依赖（GPT-4o 骨干生成的文档优于 Llama-3-70B）。

- reward_granularity
- where_deploy

### EvoSkill

> `D. 工程级自进化框架` · 开源 agent 自改进工具，扩展 GEPA 从单文件优化到完整 agent 进化

#### 基础信息

**名称：** EvoSkill
**提出机构**

Sentient（Sentient Labs）与弗吉尼亚理工大学；作者：Salaheddin Alzubi、Noah Provenzano、Jaydon Bingham、Weiyuan Chen、Tu Vu
**发布时间：** 2026-03-03（arXiv 2603.02766v1）；V1 工具包同期发布
**论文链接：** https://arxiv.org/abs/2603.02766
**代码链接：** https://github.com/sentient-agi/EvoSkill
**类型：** 工业界（开源工程框架，附带预印本论文）

#### 进化对象 (What)

**进化对象 (What)：** 上下文（记忆与提示词）以及工具/技能；整个智能体程序 = 系统提示词 + 技能集合。模型权重保持冻结。将 GEPA 的单文件提示词优化扩展为技能与提示词的联合变异，每次迭代生成一个新的智能体程序。
**技能是否独立制品**

是。技能是独立可复用的制品，以文件夹形式打包，内含 SKILL 风格的指令（markdown）、元数据以及辅助脚本。可跨智能体兼容（Claude Code、OpenCode、Codex CLI、OpenHands、Goose、Harbor）。存储于 .claude/skills/ 下并通过 git 分支进行版本管理。

#### 技能表示

**技能编码方式：** 混合形式：自然语言技能文档（.md 指令）加上每个技能文件夹内的可执行辅助代码/脚本；程序配置位于 .claude/program.yaml（系统提示词、工具、评分）。
**技能粒度：** 面向特定领域能力的子任务工作流以及可复用的代码/策略规则（如数据抽取、搜索/检索工作流）；每个技能针对一类反复出现的失败模式，而非原子操作。

#### 自进化机制 (How)

**进化方法范式 (How)**

rollout_optimization（非梯度，基于文本反馈）结合 population_evolutionary 选择。五阶段循环：基础智能体运行当前最优程序 -> 提议器分析失败轨迹并提出针对性的技能/提示词编辑 -> 生成器编写新技能文件或重写系统提示词 -> 评估器在留出验证集上打分 -> 前沿保留 top-N 个程序作为 git 分支。帕累托前沿选择仅保留能提升留出集表现的程序；每次迭代联合提出多项技能与提示词变异（相比之下 GEPA 仅做单次原地提示词修订）。
**学习信号来源：** 失败轨迹（由提议器分析的失败 rollout）以及留出验证集准确率（结果奖励）。评分器可配置：字符串/精确匹配、数值容差、LLM-as-judge 评分量表、自定义脚本，或 Harbor 内置验证器。
**奖励粒度：** outcome（完整 rollout 后的验证集准确率驱动前沿选择），辅以过程级的失败分析反馈给提议器。

#### 进化时机 (When)

**进化时机 (When)：** inter-test-time（在两次部署之间于基准/留出数据集上运行的离线自我改进循环，而非任务内的在线方式）。
**触发方式**

失败驱动（提议器针对失败用例）在周期性/可配置的迭代循环中（默认 20 次迭代，frontier_size 为 3，no_improvement_limit 为 5）。通过 `evoskill run` 由用户调用；持续/使用驱动的演化是开放的研究方向。

#### 技能存储与检索

**技能库结构**

基于 git 分支的版本化技能库：`program/base`、`program/iter-skill-*`，并以 `frontier/*` 标签标记 top-N 程序。技能以文件夹形式存放于 `.claude/skills/` 下；程序配置在 `.claude/program.yaml`。EvoSkill 仅写入以 `program/` 为前缀的分支。扁平的技能文件夹布局，采用基于前沿的选择（非层次化/向量数据库）。
**检索/复用方式：** 生成即检索：提议器分析失败并生成针对性的新技能或编辑；随后技能作为智能体上下文被直接复用（加载进系统提示词/技能目录），并打包以支持跨智能体/跨模型迁移。无语义向量检索。

#### 验证与反馈

**验证方式**

留出验证集，带验证门控（新变体只有在留出数据上超过当前最优时才能进入前沿）。基于执行的评分，通过可配置评分器实现（精确匹配、多容差、LLM-judge、脚本、Harbor 验证器）。`evoskill eval` 在验证集上重新对最优程序打分。
**错误纠正**

通过提议器/生成器循环进行自我修订，根据失败重写技能/提示词；前沿选择强制实施有界编辑（表现更差的变体被丢弃，永不进入前沿）。`evoskill diff` 与 `--continue` 支持检查与续跑。

#### 环境与基座

**测试环境**

编码/问答工具调用环境：OfficeQA（基于美国财政部数据的接地推理）、SealQA（带噪声检索的搜索增强问答）、BrowseComp（零样本迁移）、SWE-bench-verified（通过 Harbor 容器化），以及任意用户 CSV/Harbor 基准。
**底座模型**

与模型无关且冻结：Claude（Sonnet 4.6）、GPT-5/o3、GLM、Minimax、Kimi、Gemini、Qwen、Llama（Fireworks）。通过 OpenRouter/Anthropic/OpenAI/Fireworks 支持任意供应商。已验证演化技能的跨模型迁移。
**部署域 (Where)：** 通用（将通用编码智能体转化为专家）；已在编码、文档问答和网络搜索问答领域验证。

#### 评估指标

**评估指标**

success_rate（精确匹配/验证器准确率）、泛化能力（零样本跨任务与跨模型迁移）、skill_library_growth（前沿规模、发现的技能数）、成本（每次迭代的 LLM 调用数、运行墙钟时间）。
**关键结论**

OfficeQA 精确匹配 +7.3%（60.6% -> 67.9%）；SealQA +12.1%（26.6% -> 38.7%）；SealQA 演化出的技能零样本迁移到 BrowseComp 无需修改即提升 +5.3%；验证了演化出的技能文件夹的跨模型、跨智能体与跨任务可迁移性。

#### 局限与挑战

**局限与挑战**

持续（使用驱动）演化与无基准演化是开放/进行中的研究方向（当前仍需留出基准 + 验证器）。单次运行耗时数小时（通过 Docker/Daytona 远程执行缓解）。前沿选择基于留出数据存在评测黑客风险。可迁移性仅限于技能层面（模型权重冻结）。可控性取决于 task.md 与评分器质量。

### OpenSpace

**发布时间：** 2026-03-25（开源；v0.1.0 于 2026-04-03 发布）
**代码链接：** https://github.com/HKUDS/OpenSpace

#### 进化对象 (What)

**进化对象 (What)：** 工具/技能——可复用的技能产物（SKILL.md 文件）与共享技能库；非模型权重。宿主代理的上下文/提示词通过注入的技能被间接塑造。
**技能是否独立制品：** 是——每个技能都是一个独立、可复用的产物，以 SKILL.md 目录形式存储（在 SQLite DAG 中版本化，保留完整血缘与差异）；技能是一等实体，可上传/下载/共享。

**进化方法范式 (How)**

rollout_optimization（非梯度、文本空间），由 LLM 进化代理执行：对执行录像进行事后分析，生成 FIX / DERIVED / CAPTURED 编辑作为最小差异；无 SFT/RL 梯度更新。由自我反思驱动。
**学习信号来源：** 自我反思（对完整录像的事后分析）+ 成功/失败轨迹 + 环境/工具指标（工具成功率下降、技能应用率/完成率/回退率）。

**学习范式：** 离线/off-policy——进化在任务完成后通过回放执行录像进行；累积的技能以流式跨任务循环的方式被后续（不同）任务复用。

#### 进化时机 (When)

**进化时机 (When)：** inter-test-time（任务之间/之后）：事后执行分析器在每个任务后运行，并伴有周期性指标扫描与事件驱动的工具退化触发。
**触发方式：** 多触发：(1) 每个任务后的事后执行分析（成功与失败驱动）；(2) 工具成功率退化时的事件触发（批量进化依赖技能）；(3) 对技能健康度的周期性指标监控扫描。

#### 技能存储与检索

**检索/复用方式**

混合语义检索——BM25 + embedding 预过滤，再由基于 LLM 的选择（skill_ranker）完成；智能工具 RAG；CAPTURED 技能还会持久化到宿主代理的技能目录，供直接复用，或通过技能注入实现『以生成作为检索』。

#### 验证与反馈

**验证方式：** 基于执行 + 验证门控：全栈质量监控追踪技能应用率/完成率/回退率及工具成功率；进化的技能在替换前驱版本之前需经验证；确认门控+防循环守卫减少误触发。
**错误纠正：** 自我修订（FIX 模式以新版本就地修复失效/过时的指令）+ 有界/基于差异的编辑（最小化定向的 FULL/DIFF/PATCH，失败时自动重试）+ 工具退化时对上游依赖技能的级联进化。

#### 环境与基座

**测试环境**

GDPVal 基准（220 个真实世界的专业任务，44 种职业；评估了 50 任务的子集），使用 ClawWork 协议进行 LLM 评分；另演示了端到端软件构建（My Daily Monitor 仪表板）。
**底座模型**

GDPVal 基准中使用 Qwen 3.5-Plus（与基线保持一致）；通过 LiteLLM 实现模型无关——支持 Claude、GPT、MiniMax 等，以及任意宿主代理（Claude Code、Codex、Cursor、OpenClaw、nanobot）。
**部署域 (Where)：** 通用——多领域的专业工作（文档、合规/表单、电子表格、工程、媒体制作、战略与分析）；可插接到任意支持技能的代理中，并可直接作为 AI 协作者使用。

#### 评估指标

**评估指标：** 经济价值捕获（已获收入/任务最大价值）、任务质量得分、token 用量/成本效率、技能库增长（已进化技能数、版本深度）、跨任务类别的泛化能力。
**关键结论**
