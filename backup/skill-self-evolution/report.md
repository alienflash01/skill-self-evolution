## 详细内容

### Voyager

> `skill_library` · Minecraft agent，通过 automatic curriculum + iterative prompting 持续构建可复用代码技能库

#### 基础信息

**Name:** Voyager
**Institution**

NVIDIA / Caltech / UT Austin / Stanford / ASU (MineDojo team; authors: Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi "Jim" Fan, Anima Anandkumar)
**Release Date:** 2023-05-25 (arXiv v1)
**Paper Link:** https://arxiv.org/abs/2305.16291
**Code Link:** https://github.com/MineDojo/Voyager
**Type:** academic (peer-reviewed paper, arXiv preprint; MIT-licensed open-source code)

#### 进化对象_What

**What Evolved**

Tools技能 (skill library) + Context记忆与提示. An ever-growing library of executable-code skills is the evolving carrier; model weights are NOT evolved (GPT-4 used as black-box, no fine-tuning). Composition of simpler skills compounds abilities over time.
**Skill As Artifact**

Yes. Each skill is an independent reusable artifact: a self-contained executable code program plus a natural-language description, verified and committed to a persistent skill library (stored as folders) for later retrieval/composition in similar situations.

#### 技能表示

**Skill Encoding**

Executable code (JavaScript programs targeting the Mineflayer bot API, wrapped with Voyager utility functions), each paired with an NL description. Code is chosen as action space to express temporally-extended, compositional behaviors. Indexed by embedding of its description.
**Skill Granularity**

子任务workflow (sub-task programs). Each skill accomplishes a temporally-extended sub-task (e.g. 'craft wooden pickaxe', 'hunt zombie'); complex skills are synthesized by composing simpler programs.

#### 自进化机制_How

**How Method**

reward-based (environment/exec feedback as text reward) + rollout_optimization (text/code-space optimization via iterative prompting, non-gradient). Iterative prompting mechanism incorporates environment feedback, execution errors, and self-verification to improve programs; no gradient-based training or parameter access.
**Learning Signal Source**

环境反馈 (environment execution feedback + execution errors) + 自我反思 (GPT-4 self-verification as critic) + 成败轨迹 (execution success/failure). Learning is entirely in-context via black-box GPT-4 queries.

#### 进化时机_When

**When Evolve**

intra-test-time (online, during task execution). Voyager performs continuous lifelong learning, progressively acquiring/storing skills while playing in one open-ended session.
**Trigger**

curriculum-driven (GPT-4 automatic curriculum proposes next exploration tasks based on agent state + progress, an in-context novelty search) + failure-triggered iterative prompting (regenerates code on execution error or failed self-verification).

#### 存储与检索

**Library Structure**

向量库 + 技能文件. Each skill = a folder containing executable code + description; skills indexed by vector embedding of their description for similarity search.
**Retrieval Method**

语义相似度 (semantic similarity: embed skill description, retrieve top-5 relevant skills for a new task) + 代码直接复用 (direct code reuse / composition of simpler programs). The skill library also serves as a plug-and-play asset that boosts other methods (e.g. AutoGPT).

#### 验证与反馈

**Validation**

execution-based (run code in Minecraft; observe environment feedback + execution errors) + LLM-judge / validation gating (GPT-4 self-verification acts as critic to confirm task achievement; only verified skills are committed to the library).
**Error Correction**

self-revision (iterative prompting regenerates/edits the program using the error message or critique as feedback; bounded multi-round correction before a skill is accepted or rejected).

#### 环境与基座

**Test Env:** Minecraft (via Mineflayer Node.js bot + Mineflayer-collectblock; connects to a Fabric-modded Minecraft 1.19 instance).
**Backbone Model**

GPT-4 (black-box API queries for curriculum, code generation, and self-verification); ablation shows GPT-4 far outperforms GPT-3.5 for code generation.
**Where Deploy:** specialized (Minecraft / open-world game environment).

#### 评估指标

**Metrics**

skill_library_growth (new unique items discovered; library size), generalization (zero-shot transfer to unseen tasks in a new world), sample_efficiency (prompting iterations to reach milestones), success_rate (tech-tree tool tiers, task completion), exploration (unique items, map distance traveled, tech-tree milestones unlocked).
**Key Results**

Obtains 3.3x more unique items (63 within 160 iterations), travels 2.3x longer distances, and unlocks key tech-tree milestones up to 15.3x faster than prior SOTA (wooden 15.3x, stone 8.5x, iron 6.4x faster; Voyager is the ONLY method to unlock the diamond tier). Zero-shot: solves ALL unseen tasks in a new world while baselines solve NONE within 50 iterations. Skill library also plug-and-play boosts AutoGPT. Ablation: each module matters and GPT-4 >> GPT-3.5.

#### 局限与挑战

**Limitations**

transferability (skills are JavaScript/Mineflayer-bound to Minecraft, hard to port to other games/real robots), scalability (depends on costly/slow GPT-4 API calls), controllability (open-ended novelty-search curriculum may produce non-useful skills; no external goal alignment), eval-hacking risk (self-verification by same LLM that generates code). No model-parameter learning, so all knowledge is in-context/contextual; catastrophic forgetting is alleviated but not transfer across domains.

- reward_granularity
- learning_paradigm

### JARVIS-1

> `skill_library` · 开放世界 agent，基于多模态记忆的技能计划与进化

#### 基础信息

**Name:** JARVIS-1
**Institution**

Team CraftJarvis — Peking University (PKU), Beijing University of Posts and Telecommunications (BUPT), UCLA, BIGAI (Beijing Institute for General Artificial Intelligence)
**Release Date:** 2023-11-10 (arXiv v1); NeurIPS 2023
**Paper Link:** https://arxiv.org/abs/2311.05997
**Code Link:** https://github.com/CraftJarvis/JARVIS-1
**Type:** academic

#### 进化对象_What

**What Evolved**

Context记忆与提示 — a growing multimodal memory that stores successfully-executed plans/skills (goals, plans, milestone items) and is retrieved as in-context demonstrations to augment planning. No model weight updates; evolution is purely in-context/memory-based.
**Skill As Artifact**

Yes. Skills exist as reusable memory entries in a multimodal key-value store: keys = (task text + visual observation/situation), values = the natural-language action plan that was successfully executed. These persisted trajectories are independently retrievable and reusable artifacts.

#### 技能表示

**Skill Encoding**

Natural-language plans (ordered crafting/mining/smelting sub-goal sequences) paired with multimodal state keys (task text + visual observation). Text keys embedded via CLIP text encoder; visual states via CLIP visual encoder. Memory file is assets/memory.json.
**Skill Granularity**

Sub-task workflow — each skill is a decomposed chain of intermediate sub-goals / milestone items (e.g. obtain_wooden_pickaxe -> mine_cobblestone -> craft_furnace -> smelt_iron -> ...). The MLM also performs backward sub-goal decomposition for retrieval.

#### 自进化机制_How

**How Method**

imitation_demonstration (self-imitation) — only successful trajectories are saved and later retrieved as retrieval-augmented-generation (RAG) in-context demonstrations. Augmented by a curriculum-driven self-instruct exploration loop. No gradient updates, no RL.
**Learning Signal Source**

成败轨迹 (success/failure trajectories) — task success gates whether a plan is written to memory; failures are discarded, successes are stored and re-used.
**Reward Granularity:** outcome — binary task completion (target item obtained within time budget) determines memory storage.
**Learning Paradigm**

online (live Minecraft interaction); on-policy (agent's own experiences); in-context (memory-as-context, no gradient). Distributed speculative execution across shared memory accelerates data collection.

#### 进化时机_When

**When Evolve**

Both inter-test-time (multi-epoch self-improving loop: agent traverses the whole task-pool for N epochs, accumulating experiences into shared memory) and intra-test-time (within a long-horizon episode the success rate on milestone items keeps rising as game time extends and as memory grows).
**Trigger**

curriculum驱动 (LLM-self-instructed task curriculum that follows the Minecraft tech tree) across epochs; plus failure-triggered interactive re-planning (self-check/self-explain) within an episode when a sub-goal fails.

#### 存储与检索

**Library Structure**

Multimodal key-value memory (flat store indexed by task + observation). Entries organized by task/sub-goal with multimodal embeddings; optionally shared/centralized across distributed environments. Hierarchical retrieval via backward sub-goal reasoning.
**Retrieval Method**

语义相似度 (semantic similarity) via CLIP — text-embedding similarity between query and task key to filter candidates, then visual-state embedding similarity to rank; combined with generation-as-retrieval (LLM backward reasoning produces sub-goal textual queries; current visual observation is appended to form a multimodal query). Top entry per sub-goal retrieved as RAG demonstration.

#### 验证与反馈

**Validation**

execution-based validation gating — a plan is only persisted to memory after it has been successfully executed in the environment (target item obtained). Failed executions are not stored.
**Error Correction**

自我修订 (self-revision) — MLM self-check spots missing/incorrect items in the initial plan and self-explain repairs it; on execution failure the agent re-perceives state (e.g. broken pickaxe, missing fuel) and dynamically re-plans from current inventory.

#### 环境与基座

**Test Env:** Minecraft (Minecraft Universe Benchmark / MCU; native human-like observation & action space at 20 FPS, mouse+keyboard).
**Backbone Model**

Multimodal LM = MineCLIP (vision-language foundation model) chained with an LLM. LLM options tested: GPT-4, ChatGPT, LLaMA2-70B, and a Minecraft-finetuned LLaMA2-13B (≈ChatGPT). Low-level goal-conditioned controller = STEVE-1 (built on VPT).
**Where Deploy:** general (open-world generalist multi-task agent); demonstrated in Minecraft.

#### 评估指标

**Metrics**

success_rate (% episodes over >=30 seeds), long-horizon milestone completion, skill_library_growth (number of successful trajectories / memory size), cross-task transfer (success-rate gain from retrieved experiences), ablation across LLM backbones and curricula.
**Key Results**

(1) Completes >200 MCU tasks with near-perfect performance on short-horizon tasks. (2) ObtainDiamondPickaxe: 12.5% success at 60 min (6.22% at 20 min) vs 2.5%/3% for RL-finetuned VPT (SOTA) — a ~5x reliability gain. (3) Self-improving: over 4 epochs it accumulates 425 successful trajectories and success rate on intermediate milestone items keeps rising. (4) GPT-generated curriculum beats human-written and random curricula. (5) Minecraft-finetuned LLaMA2-13B matches ChatGPT; stock LLaMA2-70B underperforms due to lack of Minecraft knowledge.

#### 局限与挑战

**Limitations**

transferability (Minecraft/MCU-specific, no cross-game transfer shown); controller execution fidelity is the bottleneck for diamond-tier tasks (STEVE-1 cannot perfectly execute the LLM's short-horizon instructions); LLM planning hallucinations; situation-aware planning errors cause inefficiency/failure; open-sourced code omits multimodal descriptor, multimodal retrieval, and online learning modules (only offline fixed-memory eval released).

### GITM (Ghost in the Minecraft)

> `skill_library` · 知识图谱驱动的 Minecraft agent，技能以文本知识形式积累

#### 基础信息

**Name:** GITM (Ghost in the Minecraft)
**Institution:** Shanghai AI Lab (OpenGVLab) / Tsinghua University
**Release Date:** 2023-05-25
**Paper Link:** https://arxiv.org/abs/2305.17144
**Code Link:** https://github.com/OpenGVLab/GITM
**Type:** academic

#### 进化对象_What

**What Evolved**

Context memory & prompts (text-based knowledge and memory); LLM weights are frozen (GPT used via API). Evolves a text memory of accumulated successful action-list summaries + a text knowledge base from Minecraft wikis/recipes.
**Skill As Artifact**

Yes. Successful plans are recorded and summarized as reusable text-based memory entries ('common solutions') that serve as reference for future planning.

#### 技能表示

**Skill Encoding**

Natural language (text-based knowledge from Minecraft Wiki/recipes; text summaries of successful structured-action sequences). Not a formal graph, despite 'knowledge graph' phrasing.
**Skill Granularity**

Sub-task workflow: LLM Decomposer breaks goals into a sub-goal tree; LLM Planner produces sequences of structured actions (explore/approach/mine/equip/smelt...) for each sub-goal.

#### 自进化机制_How

**How Method**

No gradient/RL model training. Frozen GPT via API. Learns by recording & summarizing successful action lists into text memory as reusable references (self-generated successful-trajectory demonstrations / in-context exemplars). Closest to imitation_demonstration from own successful rollouts + in-context memory reuse.
**Learning Signal Source**

Success/failure trajectories: LLM Interface returns execution feedback (success/failure + inventory changes); only successful plans are summarized and stored.
**Reward Granularity:** Hybrid: per-action execution feedback (success/failure, inventory deltas) plus sub-goal outcome (goal achieved or not).
**Learning Paradigm:** Online, on-policy (agent generates its own plans/trajectories and accumulates memory during live task execution).

#### 进化时机_When

**When Evolve**

Intra-test-time (online during task execution), with memory carrying over across sub-goals/attempts to enhance future planning.
**Trigger**

Event-triggered: success events store/summarize a plan into memory; failure events trigger plan revision by the LLM Planner.

#### 存储与检索

**Library Structure**

Text-based: (1) a static text knowledge base sourced from Minecraft Wiki and in-game recipes; (2) a flat, growing text memory of summarized successful action lists.

#### 验证与反馈

**Validation**

Execution-based: the LLM Interface verifies each structured action against real environment observations (success/failure, inventory state).
**Error Correction:** Self-revision: execution failures are fed back to the LLM Planner, which iteratively corrects/refines the action plan.

#### 环境与基座

**Test Env:** Minecraft (open-world, long-horizon crafting/survival tasks, ObtainDiamond benchmark, full Overworld technology tree).
**Backbone Model:** GPT-3.5 (text-davinci) for LLM Decomposer and LLM Planner; LLM Interface uses hardcoded keyboard/mouse scripts.
**Where Deploy:** Specialized (Minecraft / open-world game agent).

#### 评估指标

**Metrics**

success_rate (ObtainDiamond), generalization (full technology-tree coverage), sample_efficiency / training cost (CPU vs GPU days), skill_library_growth (learning curve from text-memory accumulation).
**Key Results**

67.5% ObtainDiamond success rate (+47.5% over OpenAI VPT SOTA of 20%); first agent to obtain all 262 Overworld items (100% tech tree vs 30% for all prior methods combined); ~10,000x more efficient (2 days on a 32-core CPU, no GPU) vs 6,480 GPU-days (VPT) and 17 GPU-days (DreamerV3).

#### 局限与挑战

**Limitations**

transferability (Minecraft-specific text knowledge and hardcoded low-level interface scripts); scalability (depends on LLM reasoning quality and API cost; structured action set is hand-designed); limited to text-based observations rather than raw pixels.

### SkillWeaver

> `skill_library` · 分析成功轨迹，合成与精炼可复用 skill API（综述 §3.3）

#### 基础信息

**Name:** SkillWeaver
**Institution**

The Ohio State University (OSU-NLP-Group), University of Virginia, Purdue University, Carnegie Mellon University, Cisco Research
**Release Date:** 2025-04-09
**Paper Link:** https://arxiv.org/abs/2504.07079
**Code Link:** https://github.com/OSU-NLP-Group/SkillWeaver
**Type:** academic

#### 进化对象_What

**What Evolved**

Tools技能 (skill library / API action space). A growing library of reusable Python-API skills; NO model weight updates — evolution is purely in the external skill/artifact layer.
**Skill As Artifact**

Yes. Skills exist as independent, plug-and-play, transferable artifacts: Python functions (Playwright browser-automation code) each with a signature, docstring (incl. usage log + prerequisite state) and code body, stored in a knowledge base and shared across agents.

#### 技能表示

**Skill Encoding**

Executable code / API. Each skill is a Python function wrapping Playwright actions, plus a natural-language docstring recording prior executions and required preconditions.
**Skill Granularity**

子任务workflow. Three task types are abstracted into single callable APIs: procedural (multi-step automation), navigational (site mapping), and information-seeking (scraping).

#### 自进化机制_How

**How Method**

rollout_optimization(非梯度) + imitation_demonstration. Three-stage pipeline: (I) Skill Proposal (LLM auto-curriculum proposes diverse skills), (II) Skill Synthesis (agent practices tasks; an LLM reward model judges success; successful state-action trajectories are distilled into generalized Python APIs with static analysis), (III) Skill Honing (auto-generated test cases + environment feedback debug/refine APIs). No gradient updates.
**Learning Signal Source**

成败轨迹 (success/failure practice trajectories) + LLM-as-judge (an LLM reward model provides task-completion signals from trajectory + screenshots + env feedback).
**Reward Granularity:** outcome (binary task-completion success judged by the reward model per practice attempt).
**Learning Paradigm**

Online interactive exploration (agent acts in live environment) combined with offline skill distillation; on-policy (agent learns from its own trajectories).

#### 进化时机_When

**When Evolve**

inter-test-time. A self-driven curriculum exploration/synthesis phase runs offline on a new website BEFORE task execution; skills are then reused at test time. Honing also occurs during/after practice.
**Trigger**

curriculum(课程)驱动 (LLM acts as automatic curriculum proposing novel skills) + failure触发 (runtime errors during testing trigger API patching/recovery).

#### 存储与检索

**Library Structure**

技能文件 / flat per-website knowledge base. Synthesized APIs stored as code files (e.g. kb_post_code.py) with metadata; iteratively expanded over exploration iterations.

#### 验证与反馈

**Validation**

execution-based (auto-generated unit tests run the API standalone or with LLM-generated parameters) + LLM-judge (reward model) + validation gating (only verified, error-free APIs are exposed by default; --allow-unverified-apis flag controls this).
**Error Correction**

self-revision via bounded patches. On runtime exceptions during testing (--allow-recovery), the agent locates the faulty section (e.g. ambiguous DOM selector) and applies a targeted diff to make the API robust.

#### 环境与基座

**Test Env**

Web — WebArena (Gitlab, Map, Shopping, CMS, Reddit) and real-world live websites (Online-Mind2Web: Drug, Flight, Cooking, Car).

### SkillOpt

> `skill_library` · Microsoft，文本空间技能优化器；技能文档作为可训练外部状态，rollout+reflection+validation gating

#### 基础信息

**Name:** SkillOpt
**Institution**

Microsoft Research (authors: Yifan Yang, Ziyang Gong, Weiquan Huang, Qihao Yang, Ziwei Zhou, Zisu Huang, Yan Li, Xuemei Gao, Qi Dai, Bei Liu, Kai Qiu, Yuqing Yang, Dongdong Chen, Xue Yang, Chong Luo)

**Paper Link:** https://arxiv.org/abs/2605.23904
**Code Link:** https://github.com/microsoft/SkillOpt (also https://aka.ms/skillopt; PyPI: skillopt)
**Type:** academic (paper) with open-source framework (MIT license, pip install skillopt)

#### 进化对象_What

**What Evolved**

Context memory / prompt — a compact natural-language skill document is treated as the trainable external state of a frozen LLM agent; model weights are NOT updated. (category: skill_library)
**Skill As Artifact**

Yes — a single deployable best_skill.md (open SKILL.md format, ~300–2,000 tokens) that runs against the unchanged target model; reusable/transferable across models, harnesses, and nearby benchmarks; adds zero inference-time optimizer calls at deployment

#### 技能表示

**Skill Encoding:** Skill document (.md, SKILL.md format) — natural-language procedural instructions (no executable code, no vectors)
**Skill Granularity:** 策略规则 / 子任务workflow — a procedural skill document (strategic rules, heuristics, and sub-task procedures)

#### 自进化机制_How

**How Method**

rollout_optimization (non-gradient, text-space optimization). Mirrors weight-space SGD discipline: the frozen target model runs scored rollouts (forward pass), a SEPARATE optimizer model reflects on success/failure minibatches and proposes bounded add/delete/replace edits, an edit is accepted only if it strictly improves held-out validation. Uses epochs, (mini-)batch size, textual learning-rate budget, rejected-edit buffer, and epoch-wise slow/meta update. Non-gradient.
**Learning Signal Source**

成败轨迹 (scored rollout trajectories: messages, tool calls, verifier feedback, task metadata, final scores) + optimizer-side reflection (success and failure minibatches reflected separately by the optimizer model) + held-out validation score as gate
**Reward Granularity**

hybrid — outcome (final task score / held-out validation score as acceptance gate) combined with process evidence (per-example rollout trajectory analysis by optimizer)
**Learning Paradigm**

online, on-policy — fresh rollouts are collected each epoch by the target model with the current skill; offline SkillOpt-Sleep companion runs nightly replay over past sessions

#### 进化时机_When

**When Evolve**

inter-test-time (offline training phase before deployment; a nightly offline self-evolution companion 'SkillOpt-Sleep' consolidates validated skills behind a held-out gate)
**Trigger**

周期性 (epoch-driven training loop with held-out selection); SkillOpt-Sleep event-based (reviews past sessions / recurring tasks nightly)

#### 存储与检索

**Library Structure**

技能文件 — optimizes a SINGLE skill document per benchmark/domain (best_skill.md), not a multi-skill vector/graph library; one skill file per run

#### 验证与反馈

**Validation**

validation gating — a candidate edit is accepted ONLY when it strictly improves a held-out validation score (selection-best checkpoint), turning reflection into propose-and-test optimization rather than unconditional self-editing; execution-based benchmark scores
**Error Correction**

有界编辑 (bounded add/delete/replace edits under a textual learning-rate budget preventing destructive rewrites) + rejected-edit buffer (rejected edits stored as negative feedback so the optimizer avoids repeating harmful directions) + epoch-wise slow/meta update (rescues useful-but-skipped edits, longer-horizon memory without bloating deployment)

#### 环境与基座

**Test Env**

general / multi-domain across six benchmarks — SearchQA, SpreadsheetBench, OfficeQA, DocVQA, LiveMath (LiveMathBench), ALFWorld (embodied text-world); three execution harnesses: direct chat, Codex CLI, Claude Code CLI
**Backbone Model**

Frozen target models: GPT-5.5, GPT-5.4, GPT-5.4-mini, GPT-5.4-nano, GPT-5.2, Qwen3.5-4B, Qwen3.6-35B-A3B; separate optimizer model (e.g., GPT-5.5; also works with matched target-as-optimizer); multi-backend support OpenAI / Azure / Claude / Qwen / MiniMax
**Where Deploy**

general — multi-domain; deployed as a compact best_skill.md inside coding agents (Codex CLI, Claude Code CLI, Copilot) and direct chat

#### 评估指标

**Metrics**

success_rate (task accuracy), generalization (cross-model / cross-harness / cross-benchmark transfer), cost (zero inference-time optimizer calls), ablation accuracy, per-cell comparison vs baselines
**Key Results**

Best or tied-best on ALL 52 evaluated (model, benchmark, harness) cells; on GPT-5.5 lifts average no-skill accuracy by +23.5pt (direct chat), +24.8pt (Codex loop), +19.1pt (Claude Code); beats human, one-shot LLM, Trace2Skill, TextGrad, GEPA, and EvoSkill skills on every benchmark; ALFWorld test-hard 70.9%→85.8%; transfer +15.2pt cross-model, +31.8pt cross-harness (Codex→Claude Code), +10.4pt self-optimizer; ablations show textual learning rate, rejected-edit buffer, and slow/meta update each contribute gains

#### 局限与挑战

**Limitations**

scalability — optimizes a single skill document per run, not a full multi-skill library (no retrieval/indexing); requires task-level verifier / scored rollouts (needs environment feedback); gains depend on optimizer-model quality (though self-optimizer setting still works); training compute cost for repeated rollouts; controllability, catastrophic-forgetting, and eval-hacking are explicitly MITIGATED via bounded edits + held-out gate + buffer (strengths rather than weaknesses)

### Reflexion

> `experience_reflection` · 基于自我反思（verbal reinforcement）的能力迭代

#### 基础信息

**Name:** Reflexion
**Institution**

Northeastern University, Princeton University, MIT (authors: Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao)
**Release Date:** 2023-03-20 (arXiv v1); NeurIPS 2023
**Paper Link:** https://arxiv.org/abs/2303.11366
**Code Link:** https://github.com/noahshinn/reflexion
**Type:** academic

#### 进化对象_What

**What Evolved**

Context记忆与提示 (no model weight updates). The agent policy is parameterized by a long-term episodic memory of self-reflections paired with fixed LLM parameters, rather than updated weights.
**Skill As Artifact**

Yes. Self-reflective verbal feedback is stored as standalone textual artifacts in an episodic memory buffer ('mem'), persisted across trials and reused as context. Form: natural-language reflection summaries.

#### 技能表示

**Skill Encoding**

自然语言 (free-form natural-language self-reflection text generated by an LLM). No code/graph/embedding form in the core method (vector/SQL DBs suggested as future work).
**Skill Granularity**

见解 (insight). Each artifact is a verbal experience/lesson distilled from a full failed trajectory (e.g. 'I should have checked the drawer first'), serving as actionable self-hints.

#### 自进化机制_How

**How Method**

reward-based via verbal/textual feedback acting as a 'semantic gradient' signal; non-gradient policy optimization in text space (verbal RL). An Actor-Evaluator-Self-Reflection loop amplifies a sparse scalar/binary reward into natural-language feedback appended to memory to steer the next trial. No gradient/SFT/RL weight updates.
**Learning Signal Source**

Hybrid: environmental reward (compiler/test execution, exact-match grading, binary task-success), self-written unit tests (programming), LLM-as-judge / hand-written heuristics (decision-making), and self-reflection (LLM-generated verbal critique of its own trajectory).
**Reward Granularity:** outcome (a single scalar/binary reward per trajectory/trial; e.g. pass/fail, exact-match, task-complete).
**Learning Paradigm:** online; on-policy (the agent learns from its own freshly generated trajectories; no off-policy replay of external data).

#### 进化时机_When

**When Evolve**

intra-test-time (iterative online learning across repeated trials of the same task within a single solve; memory is reset between distinct tasks in the main experiments).
**Trigger**

失败触发 (failure-triggered). Loop re-runs Actor->Evaluator->Self-Reflection until the Evaluator passes or a max-trial budget is reached.

#### 存储与检索

**Library Structure**

扁平 (flat sliding-window memory). The last Omega (typically 1-3) reflection entries are kept and prepended to context; entries beyond the window are dropped. Paper notes vector-DB/SQL as future extensions.
**Retrieval Method**

Direct reuse of the sliding window: all retained reflections are concatenated into the actor prompt. No semantic/vector retrieval (collection is tiny), no workflow matching.

#### 验证与反馈

**Validation**

Execution-based validation (compiler + self-generated unit tests for coding; environment task-success for AlfWorld; exact-match grading for HotpotQA), supplemented by LLM-judge / hand-written heuristics to detect failure/non-progress (e.g. repeated-action cycles, >30 actions).
**Error Correction**

自我修订 (self-revision): on failure the agent regenerates a new attempt conditioned on its reflected lessons; for code it can also recognize incorrect self-tests and keep the prior implementation intact to avoid harmful edits.

#### 环境与基座

**Test Env**

Diverse: AlfWorld (text-world sequential decision-making), HotpotQA (multi-hop QA reasoning), HumanEval/MBPP/LeetcodeHardGym (Python & Rust code generation). LeetcodeHardGym is a new 40-question hard benchmark introduced by the paper.
**Backbone Model**

Model-agnostic LLM framework; experiments use GPT-3 (AlfWorld via ReAct few-shot), GPT-3.5 and GPT-4 (coding / reasoning). Chain-of-Thought and ReAct used as Actor modules.
**Where Deploy:** general (general-purpose across sequential decision-making, language reasoning, and programming).

#### 评估指标

**Metrics**

success_rate (AlfWorld tasks solved), pass@1 (HumanEval/MBPP/LeetcodeHard), exact-match accuracy (HotpotQA); also test-quality confusion metrics (TP/FN/FP/TN of self-generated unit tests).
**Key Results**

No weight updates / no fine-tuning. HumanEval pass@1 = 91% (beating GPT-4's 80% SOTA at the time). AlfWorld: 130/134 tasks solved, +22% absolute over ReAct baseline within 12 trials. HotpotQA: +20% improvement (CoT(GT)+Reflexion +14% over CoT(GT)). MBPP Rust 75.4%, HumanEval Rust 68%. Ablations show both test-generation and self-reflection are necessary (self-reflection alone regresses to 52% on HumanEval-Rust-50).

#### 局限与挑战

**Limitations**

scalability (memory hard-capped at 1-3 entries by context length; no persistent cross-task library); controllability (no formal success guarantee, may converge to non-optimal local minima); eval-hacking (flaky/self-written tests yield false positives, e.g. MBPP-Python regresses below GPT-4 baseline due to 16.3% false-positive test rate); transferability (reflections are task-specific, memory resets per task); strong dependence on the LLM's self-evaluation ability; reliance on isolated sandbox for autonomous code execution.

scalability (insights fit current context window, but lifelong learning would need retrieval over insights), transferability (text-only observations; no image/VLM input), controllability (prompting-based, lacks theoretical underpinnings unlike RL), dependence on closed-source API LLMs (GPT-3.5/GPT-4), room for improvement on WebShop vs Reflexion.

### Self-Refine

> `experience_reflection` · 自我迭代优化输出

#### 基础信息

**Name:** Self-Refine
**Institution**

Carnegie Mellon University (CMU) / Allen Institute for AI (AllenAI); collaborators from University of Washington, NVIDIA, UC San Diego, Google Research
**Release Date:** 2023-03-30 (arXiv v1); 2023-05-25 (v2)
**Paper Link:** https://arxiv.org/abs/2303.17651
**Type:** academic

#### 进化对象_What

**What Evolved**

Context记忆与提示 (context/prompt at inference time). No model weights or architecture are changed; a single LLM is reused as generator, critic, and refiner via prompt-only iteration.
**Skill As Artifact**

否. The refinement (feedback + improved output) is ephemeral and consumed within a single task run; no reusable skill artifact is persisted across tasks or sessions.

#### 技能表示

**Skill Encoding**

自然语言 (natural-language feedback and refined outputs). Feedback is actionable text covering problem localization + improvement instruction.
**Skill Granularity**

策略规则/见解 (insight-level actionable feedback). Multi-aspect, localized critique guiding localized edits rather than atomic actions or full workflows.

#### 自进化机制_How

**How Method**

rollout_optimization (text-space, non-gradient) combined with reward-based self-feedback. FEEDBACK -> REFINE loop: same LLM generates an internal textual reward (critique), then re-decodes the output conditioned on that feedback, iterating until a stopping criterion. No SFT, no RL, no extra weights.
**Learning Signal Source**

自我反思 / LLM-as-judge (self). The same LLM that produced the output also critiques it; no external human or environment feedback required.
**Reward Granularity**

process. Feedback pinpoints specific aspects/locations and gives concrete improvement instructions, not just a scalar outcome score.
**Learning Paradigm**

online; on-policy. Generation, critique, and refinement all happen at test time using the model's own outputs (no offline data, no off-policy corpus).

#### 进化时机_When

**When Evolve**

intra-test-time. The feedback-refine loop runs online during a single task inference; nothing is learned/trained between tasks.
**Trigger**

事件触发 (event-triggered on initial output generation). The loop starts after the initial output y0 and repeats until is_refinement_sufficient (stopping criterion) is met or a max-iteration cap is reached.

#### 存储与检索

**Library Structure**

无持久技能库 (none). Only intra-task history is kept by appending prior outputs to the prompt; no cross-task or persistent library/vector store/graph.
**Retrieval Method**

无检索 (none / in-context history only). Past iterations are appended to the running prompt rather than retrieved from a store; no semantic/keyword retrieval is used.

#### 验证与反馈

**Validation**

LLM-judge (self-feedback acts as validator) + validation gating (is_refinement_sufficient stopping function). External evaluation uses human preference and task-specific automatic metrics.
**Error Correction**

自我修订 (self-revision). The REFINE module rewrites the output guided by actionable feedback; bounded to a finite number of iterations to avoid endless loops.

#### 环境与基座

**Test Env**

通用 (general). 7 diverse benchmark tasks: dialogue response generation, code optimization, math reasoning (GSM), acronym generation, story generation, sentiment reversal/review rewriting, toxicity removal, commonsense/constrained generation.
**Backbone Model:** GPT-3.5 (text-davinci-003), ChatGPT, GPT-4 (closed-source LLMs).
**Where Deploy:** general (general-purpose text generation/refinement; not specialized to a single vertical).

#### 评估指标

**Metrics**

Human preference rate (paired human evaluation) and task-specific automatic metrics (e.g., pass@k for code, accuracy for math, BLEU/ROUGE/BERTScore for dialogue & rewriting, concept coverage, acronym scores). Iterative improvement rate per iteration also reported.

#### 局限与挑战

**Limitations**

1) transferability/capability dependence: effectiveness relies on the model's own self-reflection ability; weaker models (e.g., GPT-3.5) often give poor or misleading feedback. 2) Diminishing / negative returns after a few iterations (over-refinement can degrade output). 3) scalability/cost: multiple extra LLM calls per task increase latency and token cost. 4) No persistent learning: no skill library, no cross-task memory, so gains do not accumulate. 5) controllability/eval-hacking risk: incorrect self-feedback can steer the refinement toward worse outputs.

### Agent Workflow Memory

> `experience_reflection` · 记录可复用子任务序列（workflow），检索已验证行动链代替重规划（综述 §3.2.1）

#### 基础信息

**Name:** Agent Workflow Memory (AWM)
**Institution:** Carnegie Mellon University & MIT (authors: Zora Zhiruo Wang, Daniel Fried, Graham Neubig [CMU]; Jiayuan Mao [MIT])
**Release Date:** 2024-09-11 (arXiv v1; later accepted to ICML 2025)
**Paper Link:** https://arxiv.org/abs/2409.07429
**Code Link:** https://github.com/zorazrw/agent-workflow-memory
**Type:** academic

#### 进化对象_What

**What Evolved**

Context记忆与提示 (Context memory & prompt) — induced workflows are integrated into the agent's text memory M (system/auxiliary prompt); no model weight updates.
**Skill As Artifact**

Yes — each workflow is an independent reusable artifact consisting of an NL description (high-level goal) + a trajectory of steps (environment state description, agent reasoning, executable action), abstracting out example-specific contexts; stored in a workflow memory.

#### 技能表示

**Skill Encoding**

自然语言 (natural language) — workflow description plus NL state descriptions and actions as executable programs (e.g. CLICK, TYPE, stop()); segmented and stored as text blocks.
**Skill Granularity**

子任务workflow (sub-task workflows) — common reusable sub-routines at a finer granularity than full tasks, e.g. "search for a product", "find a place by its name", with example-specific values abstracted into placeholders like {product-name}.

#### 自进化机制_How

**How Method**

rollout_optimization (非梯度, text-space optimization) — LM-based induction module I prompts the agent to extract common sub-routines from experience trajectories and abstracts example-specific contexts; no gradients/SFT/RL. Operates in (a) offline: induce workflows from ground-truth annotated training examples; (b) online: induce from self-generated successful trajectories during streaming test inference.
**Learning Signal Source**

成败轨迹 (success/failure trajectories) — offline uses ground-truth annotated demonstrations; online uses self-generated trajectories judged successful by an LM-based evaluator (Pan et al. 2024 AutoEval binary label), only inducing workflows from judged-successful experiences.
**Reward Granularity:** outcome (binary task-level success label for online gating; no per-step/process reward).
**Learning Paradigm**

Both offline and online. Offline = off-policy (induces from given annotated examples before test). Online = on-policy streaming (induces from the agent's own predicted trajectories over test queries, in a streaming induce-integrate-utilize loop).

#### 进化时机_When

**When Evolve**

Both intra-test-time and inter-test-time. Online AWM evolves during task execution/streaming test-time (intra-test-time); offline AWM induces workflows before test-time inference (inter-test-time).
**Trigger**

事件触发 (event-driven) — online: after each test task judged successful by the evaluator, trigger workflow induction and memory update; offline: batch induction from all training examples of a website before inference. Snowball/curriculum-like effect builds increasingly complex workflows on top of earlier ones.

#### 存储与检索

**Library Structure**

扁平 (flat) — workflows stored as separate text segments in a flat workflow memory, grouped/segmented per website; each website maintains a small relevant collection of workflows. (No hierarchical/vector/graph structure; pure text blocks.)
**Retrieval Method**

工作流匹配 / in-context augmentation — workflows grouped by website; all induced workflows for the relevant website are integrated into the agent prompt context (M + W) to guide generation. Agent learns to selectively follow or diverge from workflow guidelines. (No semantic vector retrieval; website-level grouping + full injection into context.)

#### 验证与反馈

**Validation**

执行验证 (execution-based) on WebArena via functional correctness check; LLM-judge gating for online (LM-based evaluator module judges task success before inducing a workflow). Mind2Web uses element/action accuracy. Online induction is gated by evaluator success label (validation gating).

#### 环境与基座

**Test Env**

Web (web navigation) — WebArena (812 tasks, 5 websites: e-commerce/CMS/Reddit/GitLab/Maps) and Mind2Web (1000+ tasks, 200+ domains; cross-task/cross-website/cross-domain splits).
**Backbone Model**

GPT-4 (gpt-4-0613) primarily; also GPT-3.5-turbo. Temperature 0.0. Same LM used for workflow induction and action generation.
**Where Deploy**

general (general-purpose web/GUI navigation agent; demonstrated across diverse domains: travel, shopping, social media, content management, dev collaboration, maps).

#### 评估指标

**Metrics**

success_rate (task & step success rate), generalization (cross-task/cross-website/cross-domain), cost (avg number of steps per task), element accuracy, action F1, sample efficiency (learning curve over # examples).
**Key Results**

WebArena: 35.5% success rate, +12.0 absolute / +51.1% relative over BrowserGym baseline (23.5%); outperforms SteP (human expert workflows) by +7.6% relative; SOTA 35.6%; ~2 fewer steps/task, ~40.8 fewer steps than AutoEval. Mind2Web: +24.6% relative step success; offline AWM_4 step SR 45.1 vs MindAct 36.2. Online AWM generalizes +8.9–14.0 absolute step-SR points in cross-task/website/domain, with margins widening as train-test distribution gap widens. Learns from only ~40 examples (fast sample efficiency).

#### 局限与挑战

**Limitations**

transferability (online induces incorrect workflows from imperfect self-predictions, which can degrade performance; workflows are domain/website-specific) / scalability (prompt context grows as workflow memory accumulates, raising context-length cost) / workflow guidance can bias element selection (slightly lower action F1 vs MindAct; agent struggles to identify when to diverge from workflows) / online quality bounded by trajectory and evaluator accuracy.

### DRAFT (From Exploration to Mastery)

> `skill_mastery` · 迭代自纠正循环掌握/调试/精炼工具（credit-assignment + docstring refinement）（综述 §3.3）

#### 基础信息

**Name:** DRAFT (From Exploration to Mastery)
**Institution:** Renmin University of China (Gaoling School of Artificial Intelligence) & Baidu Inc.
**Release Date:** 2024-10-10 (arXiv v1); accepted ICLR 2025 (Oral, top 1.8%)
**Paper Link:** https://arxiv.org/abs/2410.08197
**Code Link:** https://github.com/quchangle1/DRAFT
**Type:** academic

#### 进化对象_What

**What Evolved**

Context记忆与提示 — evolves the natural-language tool documentation/docstrings (descriptions + parameters) fed to LLMs as context, NOT model weights nor the tool code itself.
**Skill As Artifact**

Yes — the refined tool documentation is an independent, reusable textual artifact (per-tool JSON: name/description/parameters), portable and shared across different LLMs (cross-model).

#### 技能表示

**Skill Encoding**

自然语言 (structured natural-language tool documentation / docstrings; JSON-formatted with description and parameter fields).
**Skill Granularity**

Per-tool usage documentation at the insight/guideline level (clarifies purpose, parameters, response fields, edge cases, and usage examples for a single tool).

#### 自进化机制_How

**How Method**

rollout_optimization (non-gradient, text-space iterative rewriting) + reward-based textual feedback: a self-driven trial-and-error loop with three roles — Explorer (generates diverse tool-use trials), Analyzer (LLM-as-judge that performs credit assignment, attributing failures to specific documentation deficiencies and emitting natural-language rather than scalar suggestions), Rewriter (updates the docstring). Includes diversity-promoting exploration (cosine-similarity constraint + self-reflection) and tool-adaptive termination.
**Learning Signal Source**

成败轨迹 (tool execution outcomes / return results from trials) + 自我反思 (Explorer self-reflection on duplicate queries) + LLM-as-judge (Analyzer critiques documentation vs. execution feedback).
**Learning Paradigm**

offline (documentation library refined before inference); on-policy (backbone refines docs using its own tool-usage feedback).

#### 进化时机_When

**When Evolve:** inter-test-time (offline refinement of the tool-documentation library prior to downstream inference).
**Trigger**

Periodic/iteration-driven (fixed max 5 rounds) combined with convergence-based termination (tool-adaptive stop when consecutive-doc similarity Δ > τ).

#### 存储与检索

**Library Structure:** 扁平 (flat set of per-tool documentation files; one revised doc per tool).
**Retrieval Method**

Direct reuse — refined tool docs are placed verbatim as in-context documentation for the agent at inference (no semantic skill retrieval).

#### 验证与反馈

**Validation**

execution-based (real tool/API execution feedback drives each trial) + validation gating (tool-adaptive termination via BLEU + cosine-similarity threshold τ=0.75); downstream eval via Correct Path Rate and Win Rate.
**Error Correction**

self-revision — Rewriter iteratively amends the documentation guided by Analyzer suggestions and execution feedback, with bounded iteration to avoid overfitting.

#### 环境与基座

**Test Env:** tool-call (ToolBench I3-Instruction / RapidAPI, RestBench TMDB & Spotify REST APIs).
**Backbone Model:** GPT-4o (primary DRAFT backbone); also tested Llama-3-70B as backbone; evaluated on GPT-4o, GPT-4o-mini, Llama-3-70B.

#### 评估指标

**Metrics**

success_rate (Correct Path Rate CP%, Win Rate via ChatGPT evaluator), generalization (cross-model transfer of refined docs), cost (token consumption / API cost).
**Key Results**

DRAFT-refined docs preferred by LLMs: RestBench-TMDB 92.5%, RestBench-Spotify 77.5%, ToolBench 87.9%. CP% gains for GPT-4o: TMDB 71→88, Spotify 28.07→70.17, ToolBench 37→51; GPT-4o-mini+DRAFT (CP 47) beats GPT-4o baseline (37) on ToolBench. Robust cross-model generalization (docs refined by one backbone help all models). Ablations confirm both diversity-promoting exploration and tool-adaptive termination contribute; performance peaks then degrades with too many iterations. ICLR 2025 Oral (1.8%).

#### 局限与挑战

**Limitations**

scalability (high iterative API cost per tool; expensive for large tool sets), transferability (evaluated only on tool-call benchmarks, no other domains), overfitting risk (performance declines after excessive iterations, mitigated but not eliminated by termination mechanism), backbone-dependence (GPT-4o backbone yields better docs than Llama-3-70B).

### EvoSkill

> `engineering` · 开源 agent 自改进工具，扩展 GEPA 从单文件优化到完整 agent 进化

#### 基础信息

**Name:** EvoSkill
**Institution**

Sentient (Sentient Labs) and Virginia Tech; authors Salaheddin Alzubi, Noah Provenzano, Jaydon Bingham, Weiyuan Chen, Tu Vu
**Release Date:** 2026-03-03 (arXiv 2603.02766v1); V1 toolkit release same period
**Paper Link:** https://arxiv.org/abs/2603.02766
**Code Link:** https://github.com/sentient-agi/EvoSkill
**Type:** industry (open-source engineering framework with accompanying preprint)

#### 进化对象_What

**What Evolved**

Context (memory & prompts) and Tools/skills; whole agent program = system prompt + skill set. Model weights remain frozen. Extends GEPA's single-file prompt optimization to joint skill+prompt mutation producing a new agent program each iteration.
**Skill As Artifact**

Yes. Skills are independent reusable artifacts packaged as folders containing SKILL-style instructions (markdown), metadata, and helper scripts. Cross-agent compatible (Claude Code, OpenCode, Codex CLI, OpenHands, Goose, Harbor). Stored under .claude/skills/ and versioned on git branches.

#### 技能表示

**Skill Encoding**

Hybrid: natural-language skill documents (.md instructions) plus executable helper code/scripts inside each skill folder; program configuration in .claude/program.yaml (system prompt, tools, score).
**Skill Granularity**

Sub-task workflow and reusable code/policy rules for domain-specific capabilities (e.g. data extraction, search/retrieval workflows); each skill targets a recurring failure pattern rather than atomic actions.

#### 自进化机制_How

**How Method**

rollout_optimization (non-gradient, textual feedback) combined with population_evolutionary selection. Five-stage loop: Base Agent runs current best program -> Proposer analyzes failure trajectories and proposes targeted skill/prompt edits -> Generator writes new skill files or rewrites system prompt -> Evaluator scores on held-out validation -> Frontier keeps top-N programs as git branches. Pareto-frontier selection retains only programs that improve held-out performance; multiple skill and prompt mutations are proposed jointly per iteration (vs GEPA's single in-place prompt revision).
**Learning Signal Source**

Failure trajectories (failed rollouts analyzed by Proposer) and held-out validation accuracy (outcome reward). Scorer configurable: string/exact match, numeric tolerance, LLM-as-judge rubric, custom script, or Harbor built-in verifier.
**Reward Granularity**

outcome (validation-set accuracy after full rollout drives frontier selection), with process-level failure analysis feeding the proposer.

#### 进化时机_When

**When Evolve**

inter-test-time (offline self-improvement loop run on a benchmark/held-out dataset between deployments, not intra-task online).
**Trigger**

failure-driven (proposer targets failed cases) within a periodic/configurable iteration loop (default 20 iterations, frontier_size 3, no_improvement_limit 5). User-invoked via `evoskill run`; continuous/usage-driven evolution is an open research direction.

#### 存储与检索

**Library Structure**

Versioned skill library on git branches: `program/base`, `program/iter-skill-*` with `frontier/*` tags marking top-N programs. Skills live as folders under `.claude/skills/`; program config in `.claude/program.yaml`. EvoSkill only writes to `program/`-prefixed branches. Flat skill-folder layout with frontier-based selection (not hierarchical/vector DB).
**Retrieval Method**

Generation-as-retrieval: the Proposer analyzes failures and generates targeted new skills or edits; skills are then directly reused as agent context (loaded into system prompt / skills directory) and packaged for cross-agent/cross-model transfer. No semantic vector retrieval.

#### 验证与反馈

**Validation**

Held-out validation set with validation gating (new variant only enters frontier if it beats current best on held-out data). Execution-based scoring via configurable scorers (exact, multi-tolerance, LLM-judge, script, Harbor verifier). `evoskill eval` re-scores best program on validation set.
**Error Correction**

Self-revision via Proposer/Generator loop that rewrites skills/prompts in response to failures; bounded edits enforced by frontier selection (worse-performing variants are discarded, never entering the frontier). `evoskill diff` and `--continue` support inspection and resumption.

#### 环境与基座

**Test Env**

coding / QA tool-call environments: OfficeQA (grounded reasoning over U.S. Treasury data), SealQA (search-augmented QA with noisy retrieval), BrowseComp (zero-shot transfer), SWE-bench-verified (containerized via Harbor), and arbitrary user CSV/Harbor benchmarks.
**Backbone Model**

Model-agnostic and frozen: Claude (Sonnet 4.6), GPT-5/o3, GLM, Minimax, Kimi, Gemini, Qwen, Llama (Fireworks). Any provider via OpenRouter/Anthropic/OpenAI/Fireworks. Demonstrated cross-model transfer of evolved skills.
**Where Deploy**

general (turns general-purpose coding agents into specialists); validated on coding, document QA, and web-search QA domains.

#### 评估指标

**Metrics**

success_rate (exact-match / verifier accuracy), generalization (zero-shot cross-task and cross-model transfer), skill_library_growth (frontier size, skills discovered), cost (LLM calls per iteration, run wall-time).
**Key Results**

OfficeQA exact-match +7.3% (60.6% -> 67.9%); SealQA +12.1% (26.6% -> 38.7%); zero-shot transfer of SealQA-evolved skills to BrowseComp +5.3% without modification; demonstrated cross-model, cross-agent, and cross-task transferability of evolved skill folders.

#### 局限与挑战

**Limitations**

Continuous (usage-driven) evolution and evolution-without-a-benchmark are open/in-progress research directions (currently needs a held-out benchmark + verifier). Runs take hours (mitigated by Docker/Daytona remote exec). Potential eval-hacking risk from frontier selection on held-out data. Transferability bounded to skill-level (model weights frozen). Controllability depends on task.md and scorer quality.
